## 3. 管理员权限读取其他账户（D1）

### 3.1 事实依据

- Windows 用户目录默认 ACL 只授予 `SYSTEM`、`BUILTIN\Administrators` 和本人。本机核实：`icacls C:\Users\admin` 正是这三项。
- 普通权限进程（双击启动、开机自启）在 UAC 开启时读其他账户目录会被拒绝。
- 每 5 秒一轮的**读取**都需要权限，不只是“发现”这一步。只给“重新发现”提权，后续采集仍然读不到，因此提权必须覆盖整个读取会话。
- 本机 UAC 为“管理员提权不提示”（`EnableLUA=1`、`ConsentPromptBehaviorAdmin=0`），所以本机提权不会弹窗；典型机器上会出现 UAC 确认。本机只有 `admin` 一个真实账户，验收只能依赖合成环境。

### 3.2 方案约束（计划需写成具体设计）

采用“**按需以管理员身份重启整个应用**”：

1. 设置页提供“读取其他账户（需要管理员权限）”入口和“以管理员身份重新启动”按钮。只在用户点击时提权，**启动时和自启时都不自动弹 UAC**。
2. 禁止的做法，计划里要写明并说明原因：
   - 在应用清单里设置 `requireAdministrator`：每次启动都弹 UAC，开机自启项还会被系统拦截。
   - 常驻提权的服务或辅助进程：新增特权攻击面，安装、升级、卸载都要改。
   - 修改其他账户目录的 ACL：违反只读原则。
   - 加载其他账户的注册表 hive、读取其他账户的进程环境：原计划已禁止，保留。
3. **重启流程**：
   - 用 `ShellExecuteExW("runas")` 启动同一 exe，并带上标志参数。
   - 新实例启动成功后，旧实例才退出；用户取消 UAC 时留在原实例，并提示“已取消”。
   - `tauri-plugin-single-instance`（2.5.2）在普通权限和管理员权限两个进程之间转交时，要实测并定义行为：提权实例运行中，用户又从快捷方式启动普通实例，应当怎样。UIPI 会拦截低权限进程发给高权限窗口的消息。
4. **数据目录归属（必须补的缺口）**：
   - 标准用户在 UAC 中输入的是另一个管理员账户的凭据时，提权进程以该管理员身份运行，`~` 和 `~/.tokenscope` 会指向那个账户。
   - 要求：把发起者的用户 SID 传给提权进程并核验，两者不一致时拒绝进入提权读取模式，并说明原因。不得把数据写进别的账户目录。
5. **提权后创建的文件**：
   - 管理员令牌新建文件的默认所有者可能是 `Administrators` 组。
   - 必须实测：在提权会话里新建或改写 `history.db`（含 `-wal`/`-shm`）、`settings.toml`、日志、价格快照之后，用普通权限重新启动，仍然可以读写。
6. **WebView2**：
   - 管理员与普通权限实例交替使用同一个用户数据目录时，有已知的兼容问题，必须实测“提权 → 普通 → 提权”往返。
   - 提权窗口无法接收资源管理器的拖放，所以设置页的目录选择必须用系统选择器，不能依赖拖放。
7. **普通权限会话下的展示**：
   - 其他账户的行显示“需要管理员权限”，不算错误，也不反复写 warn/info 日志。
   - 这些行先前已入库的历史用量保留并照常可查。
   - 账户列表本身来自所有人可读的 ProfileList，普通权限下也能列出。
8. **最小权限**：提权会话只额外读取其他账户的标准日志根，其余行为不变。隐私文档写明：提权会话中价格同步等网络行为照常发生。
9. **验收**：
   - 提权调用封装为可注入接口，单测与 E2E 使用替身；CI 无法点击 UAC。
   - “无权限”路径用合成目录加显式拒绝 ACE（对当前 SID 拒绝读取）来模拟。管理员身份下拒绝 ACE 同样生效，CI 上也能测。
   - 原生验收不得枚举真实 Profiles；合成 profile 提供者保持注入。

## 4. 自动识别编译进程序的非代码文件（D4）

### 4.1 事实依据

本机现有 Cargo 依赖信息文件（`target/**/deps/*.d`、`src-tauri/target/debug/*.d`）已经列出这些非 Rust 输入：

- `docs/privacy.md`（壳，`include_str!`）
- `src-tauri/capabilities`、`src-tauri/tauri.conf.json`（Tauri 构建）
- `src-tauri/src/acceptance_csp.js`（壳，以 `.js` 结尾，但属于 Rust 构建输入）
- `tests/fixtures/cache/schema-v3.sql`（核心库）
- `tests/fixtures/codex/rate-limit-only.jsonl`（**壳的测试**通过 `../../tests/...` 引用核心库的 fixture，属于跨 crate 引用）

`.github/workflows/install-test.yml` 的 `paths` 中也已经手工列入了 `docs/privacy.md`。这说明这类依赖确实存在，而且目前靠人工维护。

### 4.2 方案要求：静态扫描负责选择检查，依赖信息文件负责在 CI 校验

1. **提交钩子使用静态扫描**（毫秒级，不需要先编译），扫描暂存区快照中的以下内容：
   - Rust：`include_str!`、`include_bytes!`、`include!` 的字面量路径，按所在源文件目录解析；`concat!(env!("CARGO_MANIFEST_DIR"), "...")` 按 crate 根目录解析；`#[path = "..."]`；`build.rs` 输出的 `cargo:rerun-if-changed=`。
   - Tauri：`tauri.conf.json` 引用的图标、resources、NSIS 模板与 capabilities。
   - 前端：带 `?raw`、`?url` 的导入，`import.meta.glob`，测试中字面量路径的 `readFileSync`/`readFile`，以及 `new URL("...", import.meta.url)`。只登记 `frontend/src` 以外的目标。
   - 扫描结果形成“非代码文件 → 使用方”映射。暂存区里出现命中的文件时，按使用方执行对应检查：命中壳，跑壳的检查；命中核心库，跑 workspace 检查。
2. **无法解析的引用直接报错**：遇到宏拼接、变量路径等，选择器以非零码退出，并要求在一份受版本管理的显式登记文件里写明映射。不得静默当作无依赖。
3. **CI 交叉校验**：CI 在 workspace 构建/测试之后运行新脚本（例如 `scripts/check_build_inputs.py`），读取本次构建的全部 `*.d` 文件，滤除 `.rs`、`Cargo.toml`、`env-dep:` 和仓库外路径。剩下的每个仓库内文件都必须出现在静态扫描结果或显式登记中，否则 CI 失败。这样扫描器漏识别时会在 CI 暴露，不会一直隐藏下去。
4. **路径过滤对齐**：同一脚本检查各工作流 `paths` 是否覆盖这些构建输入，取代 `install-test.yml` 中手写的 `docs/privacy.md`；或至少在缺漏时报错。
5. **分类表修改**：
   - W05a 的“仅 `.md` 文档”规则改为“未被任何构建输入命中的 `.md`”。
   - `src-tauri/src/**` 规则改为“`src-tauri/src/**` 下的全部文件”，因为其中有 `.js`。
   - 核心库 fixture 被壳测试引用，所以核心库 `tests/**` 变化必须继续跑壳测试。原计划的 workspace 测试已经覆盖这一点，保留。
6. **测试**：W05b 增加以下用例：
   - 只暂存 `docs/privacy.md`：必须选中壳检查。
   - 只暂存 `src-tauri/src/acceptance_csp.js`：必须选中壳检查。
   - 只暂存核心库 fixture：必须选中 workspace 测试。
   - 无法解析的 include：选择器失败。
   - 依赖信息文件出现未登记的输入：交叉校验失败。

## 5. 目录嵌套、路径身份与文件级去重（D5、D8）

### 5.1 嵌套规则（D5）

- 用户手动添加时，同一应用中**与任一已有行相同、是其子目录或是其上级目录**都直接拒绝，错误信息写明冲突的那一行。“任一已有行”包括自动发现、环境变量、手动添加三种来源，已停用的行，以及目录当前不存在的行。比较同时使用规范化路径和物理身份（可访问时解析联接和符号链接）。与已有行完全相同的情况保留原规则：返回已有行，提示“目录已在列表中”。跨应用的相同或嵌套继续拒绝（SF09）。
- 删除原文中“同应用父子根保留配置行，子根先认领，父根跳过……”、状态“被子根覆盖”以及“列表注明覆盖关系”。
- **非用户点击产生的嵌套**无法拒绝，要定义确定的处理：
  - 迁移旧 `dir` 时：例如旧 Codex `dir = ~/.codex`，正好是自动根 `sessions`、`archived_sessions` 的上级。
  - 重新发现、提权后新出现账户、环境变量指向其他根内部时。
  - 处理要求：迁移和自动结果不阻断。重叠的行标为“与 X 重叠”，提示用户移除其中一行；读取时靠下面的文件级去重保证每个文件只解析一次。迁移时出现的重叠，在迁移说明里一次性告知用户。
  - S01、S03 为每种情形各补一个测试。

### 5.2 现有遍历的缺陷（必须修，且属于 PR3）

`src/source/mod.rs::walk_jsonl` 用 `child.is_dir()` 判断子目录。这个调用会**跟随**符号链接和联接，而且没有记录已访问目录。一个指向上级目录的联接会导致无限递归，最终栈溢出。

要求：

- 改用不跟随链接的 `DirEntry::file_type()` 判断类型。
- 遇到目录链接时解析目标，记录已访问目录的物理身份：目标已访问过或在另一个已启用根内，就跳过并在 debug 日志记一条；否则只跟随一次。
- 补一个“联接指向上级目录”的回归测试，修复前应当失败。

### 5.3 去重分层（D8：先比路径，再处理链接）

1. **路径层（每轮必做、开销最低）**：用规范化的绝对路径做键。
   - 处理分隔符、盘符大小写和 Windows 不区分大小写的比较。
   - `std::fs::canonicalize` 在 Windows 上返回 `\\?\C:\...` 形式，要统一成同一种写法，否则同一路径会比不上。
   - 8.3 短文件名（如 `PROGRA~1`）要还原成长文件名。
   - 根目录的规范化与物理身份只在**来源解析时**计算一次并缓存，不放进 5 秒一轮的循环。
2. **符号链接与联接层**：按 5.2 处理目录。文件级的符号链接解析到目标文件，用目标的身份去重。
3. **硬链接层**：用卷序列号加文件 ID 作为身份。
   - 优先取 128 位的 `FILE_ID_INFO`，因为 ReFS 下 64 位文件索引不唯一；取不到时退回 64 位文件索引。
   - FAT/exFAT、网络共享等没有稳定文件 ID 的位置退回路径层，并把身份标为“未确认”。
   - 取文件 ID 需要打开文件句柄。要求**按（路径、大小、修改时间）缓存文件 ID**，只对新增或变化的文件打开句柄，不得每轮对全部文件重取。
4. **确定的认领者**：同一物理文件有多个路径时，取规范化路径最小的那一个解析。解析进度按物理身份记录，认领路径变化时不从头重解析。可选优化：Codex 会话从 `sessions` 移到 `archived_sessions`（同一卷）时文件 ID 不变，可借此避免重解析；做与不做都要写明。
5. **性能验收（必须写进 S03/S06）**：
   - `perf_real_data` 实测（release）：热启动仍在现有 0.1–0.2 秒量级，相对改动前不超过 +10%；冷启动（约 5.5 秒）不超过 +10%。改动前后的数字都记进计划。
   - 合成基准：2 个根、约 2 万个文件、约 1 千个硬链接、1 个联接环。记录每轮热采集耗时与句柄打开次数；第二轮未变化时句柄打开次数应接近 0。
   - 账户枚举不进入 5 秒循环（原计划的计数测试保留）。
   - 新增“来源解析/文件身份”的阶段耗时。自动触发时按 debug 级别输出，手动和启动时按 info，符合 CLAUDE.md 的 U06 日志规约。

## 6. 环境变量（D6、D9）

### 6.1 `CODEX_HOME` 行为变更（D6）

- 现状（`src/source/codex.rs:60-77`）：`CODEX_HOME` 非空时**替代** `~/.codex`，`~/.codex` 不再读取。
- 新行为：`CODEX_HOME` 的 `sessions`、`archived_sessions` **追加**到默认根，`~/.codex` 照常读取。

## 7. 扫描状态与读取动画（D7）

- §11.2 表格中“采集结束，无新用量：立即停止读取动画”改为：**从开始算起至少显示 1 秒；真实读取超过 1 秒的，到实际结束时停止**。
- 删除 §11.2 中的“不设置最短播放时长；快速扫描允许动画短暂出现”，改为：最短 1 秒只在前端计时，**不得**拖延后端采集、不得占用串行锁、不得推迟下一轮调度、不得推迟统计刷新。有新用量时，汇总和明细照常立即刷新，“刷新中…”状态照常优先显示。
- 显示期内又收到新一轮的开始事件时，动画连续播放，不重新起播，避免抖动。
- 减少动态效果偏好下，改为显示静态读取图标和“正在读取”文字，同样至少 1 秒。窗口隐藏时不播放，恢复后不补播。不朗读开始和结束（原规定保留）。
- 心跳语义写进计划：读取正常时，状态区大约每“间隔 + 1 秒”出现一次至少 1 秒的读取动画，长时间不出现即说明读取停了。**建议**（非必须）：状态数据带上最近一次完成读取的时间，悬停提示显示“最近读取 N 秒前”，读取间隔调长时也能判断。
- **DESIGN.md 同步**：0.3.1 已写入“不用……闪烁或脉动光效”。要在其后加入明确豁免：状态区读取图标旋转（不超过 16px，中性色或强调色，无发光），每次至少 1 秒，只由真实读取触发，不属于装饰性闪烁。否则实施后与设计规范冲突。
- **测试**（F03/F04）：
  - 用可控时钟：50ms 完成的读取，动画显示不少于 1000ms，并在约 1000ms 时结束。
  - 3 秒的慢读取：动画在真实结束时停止。
  - 1 秒内连续两轮：动画不中断。
  - 有新用量：查询不等动画结束就发出。
  - 减少动态效果偏好下：显示静态图标，同样不少于 1 秒。
