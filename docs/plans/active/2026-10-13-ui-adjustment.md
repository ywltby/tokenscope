# UI 调整计划：时间筛选、汇总页状态与设置页

> 状态：**待用户确认，未开始实施。** 确认后按 U01 → U06 顺序执行，每项先写能红的测试再改实现。

**Goal:** 让用户始终看得到"现在统计的是哪段时间"，修掉时间与时区被旧视图改写的两个缺陷，收敛汇总页的状态管理，并把设置页整理成分区清楚、文案与实现一致的页面。

**Architecture:** 时间范围改为"预设 + 查询时解析"，由后端在查询入口一次冻结并回传解析后的日期；视图快照只负责首帧展示，不再写回筛选和偏好。汇总页查询编排抽成一个组合式函数，页面切换保留状态。设置页按分区展示，界面文案改为与历史库实现一致。

**Tech Stack:** Vue 3 / Naive UI / Vitest；Rust（`query.rs`、`report.rs`、`settings.rs`）与 Tauri 命令层。

## 2. 已核实的问题（证据）

1. **从设置页改时区后回到汇总页，会被改回旧值**（已用临时 Vitest 探针复现，探针未入库）：时区设为 `UTC` 后挂载汇总页，`view_cache_load` 返回旧快照（`tz: Asia/Shanghai`），结束后全局时区变回 `Asia/Shanghai`，`localStorage` 也被写回旧值，并多发一次 `query_begin`。根因在 `Dashboard.vue` 的 `loadViewCache` 里把 `cached.filters.tz` 写进全局时区 ref（`tz.value = cached.filters.tz`）；汇总页用 `v-if` 切页，每次回来都重新挂载并恢复快照。
2. **“今天 / 近 N 天”被存成死日期**：快照 `filters.range` 只存 `[from, to]`，第二天打开仍是旧区间；“结束日跟随今天”只在点确定那一刻求值一次。
3. **页面上看不到当前时间范围**：日期触发器只有图标，范围只在悬停提示里（截图 `qa-artifacts/privacy-consent/normal-light-1280x820.png`）。
4. **日期弹层操作绕**：弹层里有两个独立的 `NDatePicker`（弹层套弹层）、快捷按钮、跟随今天勾选和取消/确定；选一个快捷项要点三次。
5. **汇总页状态管理靠补丁叠加**：`Dashboard.vue` 脚本约 640 行，有 `summarySeq`、`eventsSeq`、`refreshEpoch`、`interactionEpoch`、`beginEpoch`、`applyingRestore`、`freshArrived`、`disposed`、`liveFirstPage` 九套并发守卫；问题 1 是其副作用。
6. **页面切换不对称**：汇总页 `v-if` 每次重建（丢下钻、丢滚动位置、恢复旧快照），设置页却是 `KeepAlive`。
7. **汇总页通知条各自堆叠**：最多七种（来源检测失败、来源异常、汇总失败、采集诊断、日汇总时区不一致、仅明细模式、明细失败），与 DESIGN.md §5“多条合并成一条并可展开”不符。
8. **小问题**：下钻提示显示为 `model: xxx`（中文界面混英文类型名）；合计行靠字面量 `"合计"` 判断。
9. **设置页**：
   - 一长页七组，上千行价格表夹在中间；“Token 显示颜色”排在最前。
   - “缓存”分组写着“缓存是纯优化：任何故障都会自动退回全量扫描”，但该处读的是 `history.db` 历史库计数（`report.rs` 中 `CacheInfo` 的注释已写明），历史库是持久事实存储，这句话误导。
   - 内部审计编号上屏：CCS 预览说明含“I-P3-2：保证与可导入逐行闭合”。
   - 来源统计时区说明里的 `**这个时区**` 在 Vue 模板中会原样显示星号。
   - 价格候选规则六行说明直接铺在页面上，违背“说明能收进提示就收进提示”。
   - 保存方式不一致：时区/颜色/自启即改即存；数据源逐个点“保存”且“回到汇总页生效”。
10. **时区存放位置不一致**：时区在浏览器 `localStorage`（`tokenscope-tz`），其余设置在 `~/.tokenscope/settings.toml`；时区又同时是视图快照筛选的一部分。

## 3. 必须保持的不变量

1. 一次查询只在入口解析一次“今天”并冻结（SF05）；预设近 N 天 = 统计时区 `[今天-(N-1), 今天]` 闭区间。前端不自行计算预设的具体日期用于查询。
2. 展示的时间范围文字必须来自本次查询冻结的结果（后端回传），与汇总数字同源；不得出现“标签是今天的、数字是昨天快照的”。
3. 视图快照**只读展示**：恢复快照不得修改时区偏好、不得改写用户当前选的筛选；快照时区与当前时区不一致时不使用该快照。
4. 时区只有一个持久化来源。
5. 只显示图标与固定两行的筛选栏形态不变；玻璃材质、tokens、柔光背景不变。
6. 业务口径不变：四桶、费用 breakdown、下钻身份键、分页游标 v2、`query_expired` 处理全部保持。
7. 测试密闭性：新测试不得读写真实 `~/.tokenscope`。

## 4. 任务

### U01 时间范围预设化与显示（问题 2、3）

- 前端时间状态改为预设：`{ kind: "all" } | { kind: "last", days: N } | { kind: "since", from } | { kind: "custom", from, to }`。预设查询传 `days`，`since` 只传 `from`，`custom` 传 `from/to`（后端 `TimeBounds::resolve` 已支持，三者互斥）。
- 后端 `QueryHandle` 与 `SummaryReport` 增加本次冻结的解析结果：`range_from` / `range_to`（可空）；“全部时间”时另给本次快照内事件的最早/最晚自然日 `data_from` / `data_to`（统计时区，空数据为 null）。
- 汇总页标题下副标题显示范围，不显示时区：
  - `近 7 天 · 10/6 – 10/12`、`今天 · 10/12`、`10/1 – 今天`、`2026/3/14 – 2026/4/12`、`全部时间 · 2026/3/14 – 10/12`、无数据时 `全部时间 · 暂无数据`；
  - 年份规则沿用 `rangeLabel`（非当前年或跨年才带年份）；
  - 有下钻时同一行追加 `· 已筛选 模型：xxx`。
- 日期图标触发器保持只显示图标；“有范围时强调色”规则不变（`all` 不着色）。
- 视图快照版本升至 v12，`filters.range` 存预设对象；v11 及更早快照按“不使用”处理。
- 同步修改 DESIGN.md §4 布局示意与 §5 筛选栏条目（“副标题显示当前时间范围，不显示时区”）。
- 先写的测试：
  - 预设“近 7 天”保存快照后，把模拟时钟推进一天，再挂载：`query_begin` 收到 `days: 7` 而非旧日期；
  - 副标题文字取自后端回传的 `range_from/range_to`，不取前端时钟；
  - Rust：`days`/`from`/`to` 三种入参回传的解析日期正确，跨日界由 `as_of` 决定；全部时间的数据跨度正确，空库为 null。

### U02 日期弹层简化（问题 4）

- 快捷项（当天、近 2 天、近 7 天、近 14 天、近 30 天、全部时间）点一下立即生效并关闭弹层。
- “自定义”区改为一个内联的区间选择面板（Naive `NDatePicker` `type="daterange"` 的 `panel` 形态；实施前先确认当前 naive-ui 2.45 支持，不支持则保留单个触发式区间选择器），附“结束日跟随今天”（生成 `since` 预设），只有自定义需要“确定”。
- 不再有两个独立日期选择器嵌套弹层；浮层材质仍只有一层（RC09）。
- 先写的测试：快捷项一次点击即发出新预设并关闭；自定义确认产生 `custom`；勾选跟随今天产生 `since`；Escape / 取消不改值；键盘可完成全部操作。

### U03 时区单一来源（问题 1、10）

- 时区移入 `settings.toml`（新字段 `timezone`，缺省 `Asia/Shanghai`，合法值 `local` 或 IANA 名），读写走 `settings::update` 事务；首次启动若 `localStorage` 有合法旧值则迁移一次后删除旧键。
- `useTimezone` 改为读后端设置；设置页修改即保存，失败显示局部错误并回滚显示值。
- 视图快照不再写时区；快照时区与当前时区不同则丢弃快照。
- 先写的测试：把本次探针改成正式回归——设置时区为 UTC、快照为 Asia/Shanghai，挂载后时区仍为 UTC，且只发一次 `query_begin`，参数 `tz: "UTC"`；Rust：缺省值、非法值拒绝保存、旧 settings.toml 无该字段时读取正常。

### U04 汇总页查询编排收敛（问题 5、6、7、8）

- 把会话建立、汇总、明细、分页、快照保存与恢复抽成 `composables/useUsageQuery.ts`：一个批次编号负责丢弃过期响应；快照恢复只填充展示数据并标记 stale，不触发筛选 watcher、不写偏好。其余守卫按行为逐项迁移并删除，现有 `Dashboard.test.ts` 用例全部保留并通过。
- `MainApp.vue` 汇总页改为 `KeepAlive`；切回汇总页时在后台刷新数据，保留筛选、下钻与滚动位置，不再重建组件、不再恢复磁盘快照。
- 通知条合并为一条：显示最高严重级别与条数，展开后逐条列出，各自的“重试 / 去设置 / 只看请求明细 / 恢复自动参与”动作保留在条目上。

- 先写的测试：切到设置再回来，下钻与筛选保留且只发一批查询；同时存在三类问题时只渲染一条通知、展开后三条且动作可用；下钻提示文本为中文。

### U05 设置页分区与文案（问题 9）

- 设置页左侧分区导航，一次显示一个分区（`v-show` 保留草稿）：通用（时区、开机自启、关闭窗口）、数据源、用量数据（历史库统计、重扫日志、从 CCS 导入）、价格（同步、外置价格文件、自动同步、价格表）、外观（Token 显示颜色）、高级（打开设置文件）。价格表在首次进入“价格”分区时才挂载；窄窗口（≤1100px）导航改为顶部分段控件。导航与分区样式沿用现有 `.ts-card` 与分段控件，不新增材质。
- “缓存”改名“用量数据”，计数标签改为“已采集文件 / 已保存请求”，说明改为：用量保存在 `history.db`，来源日志删除或停用后已保存的用量仍保留；重扫只重新解析日志，不删除历史。后端 `cache_stats` / `CacheInfo` 等内部命名本轮不改。
- 删除 CCS 预览中的“I-P3-2：保证与可导入逐行闭合”；`**这个时区**` 改为 `.ts-strong` 强调；价格候选规则长说明收进 `HelpTooltip`，页面只留一句结论。

- 先写的测试：设置页文本不含 `I-P3-2`、不含字面 `**`；分区切换保留未保存草稿；价格表在进入价格分区前不挂载；数据源保存成功后切回汇总页触发刷新。
