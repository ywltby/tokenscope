> 状态：[审阅第 13 节](../../reviews/2026-10-15-source-discovery-plan-review.md)复审通过；F01–F05 未实施。PR1 已合入 main（`19aae8b`）；按用户 2026-10-16 决定，须等[升级测试补测计划](2026-10-16-upgrade-matrix.md)（含原生验收重启修复 UP09）合入后再开工，F04 基于其新的实例生命周期扩展原生验收。
> 前置条件：[PR1 目录迁移](2026-10-15-workspace-layout.md)已合入 main。实施时从最新 main 创建 `feat/collection-status`，独立 minor 和独立门禁，不依赖 [PR3 来源管理](2026-10-14-source-discovery-and-additional-paths.md)；PR3 在本 PR 合入后再启动。

**Goal：** 扫描由真实工作驱动、至少显示 1 秒，作为可见读取心跳；只有新事实或既有时间窗口规则触发统计刷新，取消常驻具体更新时间。

**Architecture：** 核心串行采集边界发布生命周期，Tauri 提供事件与只读快照，前端分开维护真实阶段和最短显示期。统计查询不等待动画。

本计划取代旧 UI 调整 U06 的常驻“更新于 HH:MM:SS”要求；分页保护、冻结会话和窗口可见性规则保留。

## 1. 原因与范围

“每 5 秒自动读取”指上一轮采集结束后等待 5 秒，再扫描来源；不是每 5 秒必然产生新的 token 用量。现有状态时间来自统计查询的 `as_of`，不代表最近扫描时间。没有新事实时，后台不发 `usage-updated`，界面时间保持不变，用户无法据此判断采集是否正常工作。

2026-10-15 本机只读排查：源日志用量记录时间 00:16:01.265，对应入库 00:16:05.041；截图 00:16:27 显示“更新于 00:16:05”；下一笔源用量时间 00:16:46.565，入库 00:16:52.082。该片段没有证实 UI 漏刷。源记录时间不等同于操作系统实际落盘时间，现有 info 日志也不能证明无变化期间每一轮扫描执行时刻。原始会话内容、身份和路径不纳入文档或 fixture。

F 组任务只改扫描反馈，不改变用量解析、去重、价格、自动读取间隔或 CCS 手动导入规则。不改成定时强刷统计，不新增常驻时间字段，不增加每轮 info 日志。

## 2. 界面契约

| 实际状态 | 状态区 | 统计数据 |
| --- | --- | --- |
| 初始状态尚未获取 | 正在确认状态，静态 | 保留已有视图，不假称扫描中 |
| 等待下轮，已有有效统计，无错误 | 静态绿点“已更新” | 不变 |
| 后台实际开始采集 | 旋转图标“正在读取” | 保留已有视图 |
| 采集结束，无新用量 | 从开始至少显示 1 秒；已满 1 秒则结束，恢复静态状态 | 不触发新查询 |
| 采集结束，有新用量 | 读取显示期仍遵循最短 1 秒；查询在途优先显示“刷新中…”及加载图标 | 立即发查询，不等动画；汇总与明细同批成功后替换 |
| 有新用量，但明细已加载更多 | 静态“有新数据 · 刷新” | 保留已加载页，用户点击后刷新 |
| 采集失败 | 动画停止，“读取失败”，提供可操作错误提示 | 保留旧统计；不能显示正常“已更新” |
| 采集成功但存在部分来源/坏行问题 | 满足最短显示期后停止，诊断立即显示，状态体现部分异常 | 有效用量仍可立即更新 |
| 查询失败 | 查询加载停止，“刷新失败 · 显示上次数据” | 不覆盖旧统计 |

状态优先规则：活动阶段显示当前工作；错误持续保留在独立提示中，不能被另一路成功清除。后台下一次成功只能清除采集错误，成功查询才能清除查询错误。没有首批有效统计时不能显示“已更新”。

悬停说明：“每 5 秒自动读取；无新用量时保持统计不变”（间隔使用已保存的有效配置）。取消常驻具体更新时间；内部 `as_of`、快照时间及日志不删除。设置页帮助文案同步解释自动保存、扫描频率及有变化才刷新。

动画仅由真实 start 触发，静态 SVG 的外层使用 CSS transform 旋转；从可见 start 起最少 1000ms，实际读取更久则到真实结束才停止。最短期仅在前端实现，不延迟后端、串行锁、下一轮调度或统计查询。有新数据时查询立即启动且“刷新中…”优先，保持同一加载图标连续；查询先结束而读取最短期未满时仍显示读取反馈到期，不延迟结果。显示期内新 start 不重置旋转相位，每轮至少持续到自己的 start＋1000ms 且真实工作已结束；多轮不闪断。

减少动态效果时静态图标＋文字也至少 1 秒。读取失败/状态不可用优先立即停止并显示错误，不用最短期掩盖异常。隐藏时清除显示计时器，不补播已完成轮次；恢复仍在 running 则按当前运行状态展示。卸载清理计时器。不抢焦点，不朗读每轮 start/end。

心跳让用户看到采集发生过，但不能单靠“没看到动画”判定后台停止（可能隐藏或事件通道异常）。周期仍为配置间隔＋真实采集耗时，并非间隔＋强制 1 秒；例如 5 秒间隔、50ms 读取约每 5.05 秒开始一次，图标显示 1 秒。最短显示不改变调度。DTO 增加 lastCompletedAt（UTC 或 null），tooltip 可显示“最近读取 N 秒前”便于诊断，不常驻精确时刻，也不将它作为统计 as_of。

DESIGN.md 明确加入豁免：状态区不超过 16px 的读取图标 CSS 旋转、中性色或强调色、无发光，真实读取触发、至少 1 秒，是功能反馈，不属于被禁止的装饰性闪烁或脉动。现有第三方加载图标不在本 PR 无差别替换。

窗口隐藏时不执行统计刷新、不播放动画；后端照常采集。恢复时查询当前状态，按代次补齐变化，并保留分页保护；不得补播隐藏期间已经完成的扫描。

## 3. 后端状态与事件

### 3.1 真实边界与单飞

修改 `crates/tokenscope-core/src/report.rs` 的 `collect_flighted_with`：仅领队取得 `COLLECT_SERIAL` 串行锁后进入 running，结束采集工作后进入终态；单飞跟随者不创建轮次，等待串行锁不算正在读取。启动、手动刷新、定时采集共用这一边界，避免定时入口动画遗漏手动采集或把排队时间算成扫描。

根库提供可注入的状态观察接口及内存快照，不依赖 Tauri。状态更新后释放状态锁，再通知观察者；观察者失败不能改变采集结果。终态覆盖成功、返回错误与 unwind，RAII 收尾不能在 panic 时伪报成功；进程直接终止不承诺发结束事件。无业务权限时跳过定时轮次，不制造成功扫描。退出中不启动新轮次。

建议统一状态 DTO：

```typescript
type CollectionStatus = {
  revision: number; // 进程内每次状态转换单调递增，IPC 限安全整数
  runId: number; // 仅真正执行的领队递增
  phase: "idle" | "running" | "succeeded" | "failed";
  trigger: "startup" | "manual" | "auto" | null;
  latestGeneration: number | null; // 最近成功采集的历史代次，失败不清空
  changed: boolean; // 本轮是否有事实变动，不以文件 mtime 代替
  hasWarnings: boolean;
  lastCompletedAt: string | null; // 最近成功或失败的完成时间，非查询 as_of
  error: string | null; // 精简可展示错误，完整链仅写现有日志
};
```

初始 idle 不意味着统计已经更新。保存最近成功代次，使最后一轮无变化时仍能修复前端漏掉更早通知的情况。普通状态不带文件路径、模型列表或用量事实；诊断内容沿用既有查询渠道。

### 3.2 Tauri 接线与恢复

`src-tauri/src/lib.rs` 在业务 Ready 后注册一次观察者并发送 `collection-status` 事件；状态终态发出不等于统计查询已经完成。保留 `usage-updated`，不重复增加第二条无条件刷新链路。

`src-tauri/src/commands.rs` 新增只读 `collection_status`，仅返回内存快照；在命令注册和 `src-tauri/src/privacy.rs` 中接入 Ready 权限检查。查询状态不能扫描目录、打开历史库或导入 CCS。

前端先订阅，再调用状态查询；只接收较新 revision，避免查询晚到覆盖刚收到的事件。监听失败不得静默显示正常状态，显示“读取状态不可用”，允许重试。窗口恢复、组件重新挂载时重查；可见期间每 30 秒仅查询一次内存状态以纠正漏失结束事件，失败时停止假定动画并提示状态不可用，不把超时假判为采集失败。隐藏时停止该校验计时器，卸载时清理订阅和计时器。

状态恢复得到比当前统计快照更高的 latestGeneration 时走现有自动刷新合并入口；与 `usage-updated` 交叉到达时，同一已覆盖代次不再重复建查询。查询在途、分页、隐藏保护继续有效。状态 revision 和历史 generation 各自独立，不能混用。

## 6. 执行细则与逐项验收门槛

先遵守 [PR1 第 4 节共同执行约束](2026-10-15-workspace-layout.md#41-开工与逐项执行)及其证据/门槛。本节只细化 F01–F05，不授权在 PR1 合入前实施。新接口先补测试，任务执行记录中填实际 commit、命令、退出码和工件。

### 6.1 F01/F02：真实状态机，先内核后 IPC

1. 在 report.rs 定位单飞的领队分支、串行锁、历史提交与结果发布位置，画出调用顺序并记录。状态只能包住真正采集的领队闭包；调用 recent_collection 命中的查询不能产生 start。
2. 新建可隔离状态存储：`idle → running(runId+1) → succeeded/failed`。每次转换 revision 增加；结束保留本轮 runId。start 将本轮 changed/error 清零，但不清空最近成功 generation。失败不推进成功 generation，终态时间记录该轮完成时刻。
3. start 在取得采集串行锁后发出；终态在采集闭包及历史提交结果确定后发出，在释放串行锁前完成内存状态转换，避免下一领队 start 被上一领队 end 覆盖。观察者通知必须在状态锁外，不允许同步回调重入采集；Tauri 桥只做轻量事件投递，不查询或扫描。
4. RAII guard 默认失败，只有采集成功并取得实际结果后显式提交成功；Drop 不能 panic、不能吞原始错误或把 unwind 转成成功。观察者错误单独记录，不改变已提交用量。测试观察者重入状态读取不会死锁。
5. 同 key 并发请求用屏障控制：只有一对 start/end；不同 key 排队用屏障验证第二轮取得串行锁前没有 start。不能用短 sleep 假定线程顺序。全局状态相关测试共用串行锁，其他状态机测试用独立实例。
6. F01 全部通过后再接 Tauri 观察者与 command。Ready 前命令拒绝；Ready 后连续查询状态不改变 runId/revision、历史库或采集调用次数。观察者只注册一次；重建窗口不能重复注册。

阻断断言：任一实际领队缺 start/end、跟随者多出轮次、失败伪成功、状态查询触发读取、观察者持状态锁被调用，均不得进入前端验收。

### 6.2 F03：拆开真实状态、显示计时和统计刷新

建议在 `collectionStatus.ts` 中分开保存 `latestStatus`、`visible`、`displayUntil`、`statusUnavailable`；统计数据与 query_id 继续由 `useUsageQuery.ts` 管理，不复制第二套统计快照。

```text
接收状态：
  revision <= 已接收 revision：忽略（包括迟到的 IPC 回复）
  更新真实状态；状态恢复的 generation 交给已有自动刷新合并入口
  隐藏：不开始显示计时，不发统计查询，只记待刷新
  failed / 状态通道不可用：立即清除显示计时，展示独立错误
  可见新 runId 的 running：displayUntil = max(旧截止, 单调时钟 now + 1000ms)
  running 或 now < displayUntil：保留读取反馈
  其他终态：停止读取反馈
```

1. 计时使用可注入单调时钟，不用系统日期算持续时间；相同 runId 的重复快照不延长 1 秒。新 start 只延长截止，不卸载重建图标、不重置 CSS 相位。
2. 先注册监听，再查询快照；初次快照前显示确认状态。组件销毁先标失效，再清理订阅和全部 timer；已经发出的 IPC 晚到也不能更新卸载组件或重建 timer。
3. 接收更高 generation 时调用已有的“有新数据”入口；统一管理已覆盖代次、在途目标代次与待刷新代次。不能在两个 composable 各自直接 query_begin。读取 min-duration 计时器绝不调用查询。
4. native 窗口可见性保持权威，隐藏期间无统计查询、无 30 秒校验、无动画 timer；恢复重查状态，已完成轮次不补播，仍 running 的轮次才展示。分页保护比自动刷新优先。
5. 设置页保存间隔走已有自动保存/调度，不新增保存按钮，不另设 UI 的扫描 interval。tooltip 使用已保存值；失败保存不能假显示新间隔已生效。
6. 更新 Dashboard/Settings 和 DESIGN.md 后，定向跑 collectionStatus/useUsageQuery 测试，再跑完整前端门禁。不要全局替换第三方 SVG 或改变其他加载控件。

### 6.3 F03/F04 必需反例表

| 输入序列（可控时钟/受控采集） | 必须观察到 |
| --- | --- |
| start t=0，success 无变化 t=50ms | t=999ms 仍显示，t=1000ms 可停止；query_begin 增量 0，query_id 不变 |
| start t=0，success t=3000ms | t=1000ms 仍显示，完成后停止；不多等 1 秒 |
| 两轮 start 分别 t=0、t=500ms，均很快结束 | 连续显示至至少 t=1500ms；旋转节点/相位不重建 |
| t=50ms 有新事实并结束，查询 t=100ms 完成 | 查询早于 1000ms 发出且结果立即发布；读取反馈继续满足最短期 |
| 相同代次 usage-updated 与状态恢复交叉到达 | 只建一个刷新批次；在途新增更高代次只补必要下一批 |
| 旧 revision 快照晚于新事件到达 | 不倒退阶段、不覆盖错误、不重新开始计时 |
| 失败 t=50ms、随后一次成功 | 失败立即停，不等 1000ms；仅清采集错误，不清查询错误 |
| 已加载更多后新事实到达 | 不替换明细，只提示；手动刷新后查询身份一致 |
| 隐藏跨过两次读取再恢复 | 隐藏无查询/动画；恢复至多合并刷新，不重播两次动画 |
| 降低动态效果、组件卸载、通道断开 | 静态提示满足最短期；卸载无遗留 timer/listener；通道失败不能一直转圈 |

前端 fake-clock 测试严格检查 999/1000ms 边界；原生 E2E 记录观察误差，不用截图间隔推断精确 50ms 后端时长。原生快速完成可按实际时间记录，1000ms 精确阈值由可控时钟证明；不得给生产扫描硬加 50ms/1s 延迟来凑结果。

F04 必须同时有浏览器契约与真实 Tauri 隔离实跑。证据至少含进程/构建身份、runId/revision、开始/结束、显示开始/结束、generation、查询批次和事实前后差异。合成一条新事实的身份及四桶期望预先写死；不能只断言“总数大于原来”。慢轮次与故障仅由测试构建注入。工件缺关键场景、状态事件由测试直接伪造而未走采集入口，均不能标原生验收通过。
