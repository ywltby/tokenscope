**Architecture:**
- 时间范围用“预设”表示，后端在查询入口冻结 `as_of` 后一次算出边界（自然日或时刻两种模式）并回传。

- 筛选偏好与视图快照分开保存；时区与读取间隔放在 `settings.toml`，串行保存。

**Tech Stack:** Vue 3 / Naive UI 2.45 / Vitest；Rust（`report.rs`、`query.rs`、`settings.rs`）与 Tauri 命令层（`src-tauri`）。

## 2. 已核实的问题与现状

1. **改了时区，回到汇总页会被改回旧值。** 已用临时 Vitest 探针复现（未入库）：时区设为 `UTC`，加载到旧快照（`tz: Asia/Shanghai`）后，全局时区和 `localStorage` 都被改回 `Asia/Shanghai`，还多发了一次 `query_begin`。直接原因是 `Dashboard.vue` 的 `loadViewCache` 把快照里的 `tz` 写进了全局时区 ref。汇总页用 `v-if` 切页，每次回来都会触发。
2. **“近 N 天”被存成固定日期。** 快照只存 `[from, to]`；“结束日跟随今天”只在点确定的那一刻求值一次。
3. **看不到当前时间范围。** 日期按钮只有图标，范围只在悬停提示里。
4. **日期弹层操作绕。** 两个独立的 `NDatePicker` 弹层套弹层，选一个快捷项要点三次。
5. **汇总页状态分散。** `Dashboard.vue` 脚本约 640 行，九个并发相关状态各自承担既有回归保护；“快照恢复”和“用户筛选”共用同一组状态，可以互相改写。
6. **两页切换不一致。** 汇总页 `v-if` 重建，设置页 `KeepAlive`；滚动容器在 `MainApp.vue`，切页不分别保存滚动位置。
7. **汇总页最多同时出现七种通知条**，不符合 DESIGN.md §5“合并成一条并可展开”。
8. **下钻提示显示为 `model: xxx`；合计行靠字面量 `"合计"` 判断。**
9. **设置页：**
   - 一长页七组，价格表夹在中间；
   - “缓存”分组声称“纯优化、故障退回全量扫描”，但读的是持久历史库 `history.db`；
   - 界面上出现审计编号“I-P3-2”；
   - `**这个时区**` 的星号原样显示；
   - 价格规则长说明直接铺在页面上；
   - 数据源要求“回到汇总页生效”。
10. **时区存在 localStorage，又作为快照筛选的一部分被恢复，没有唯一权威来源。** 主题与颜色也在 localStorage，但只影响外观；时区影响统计口径，所以放进 `settings.toml`。
11. **自动读取现状：**
    - 后台定时线程固定每 300 秒采集一次（`src-tauri/src/lib.rs` 的 `COLLECT_INTERVAL`，首轮延迟 30 秒），调用 `report::summary`，即采集、建快照、聚合全做一遍，读完不通知界面；
    - `query::begin_query` 每次都先采集（`report::collect_flighted`）；单飞协调器只合并同时在途的请求，不复用已结束的那一轮；
    - `report.rs`、`query.rs`、`commands.rs` 这几条路径上共有 27 处 `log::info!`，按 5 秒间隔会刷屏；
    - 手动“刷新”按钮在标题行右侧，但不显眼，状态胶囊只写“已更新”。
12. **其他代码事实：**
    - 查询会话最多 8 个（`query.rs` 的 `MAX_ACTIVE_QUERIES`）；
    - 自然日过滤 `TimeBounds::matches` 只比较日期，不排除今天晚于 `as_of` 的记录。

## 3. 必须保持的不变量

1. **一次查询只取一次 `as_of` 并冻结（SF05）。** 前端不计算查询用的边界，只发预设参数。
2. **两种边界模式，所有模式都排除晚于 `as_of` 的记录。**
   - **自然日模式**：事件在统计时区的日期属于 `[from, to]`，且时刻 `≤ as_of`。包括快捷项“当日 / 7d / 14d / 30d”、整日自定义和整日至今。日汇总按现有规则参与。范围包含今天时，会包含今天已有的日汇总；这是自然日模式的既有语义（与现在的“当日”一致），视为有意的例外，不当作时刻范围处理。
   - **时刻模式**：
     - 24h 为 `as_of - 24h ≤ ts ≤ as_of`；
     - 自定义为 `start ≤ ts < end_exclusive`，且 `ts ≤ as_of`；
     - 日汇总不参与，也不按比例估算。
3. **界面显示的范围取自后端回传的冻结结果，与汇总数字同源。**
4. **单一查询身份。** 页面上同时显示的汇总与明细必须属于同一个 `query_id`；任何时候都不拼接两个会话的数据，也不持久化这样的组合。
5. **筛选偏好决定“查什么”。** 筛选偏好（来源、维度、时间预设、日粒度参与方式、下钻）独立持久化。视图快照只在与当前偏好和时区逐项相等时用于首帧展示，从不反向改写偏好或时区。
6. **时区与读取间隔的唯一来源是 `settings.toml`。** 首次查询在时区读取完成之后发起；同一设置项的保存串行执行，最终落盘值等于用户最后一次选择。
7. **自动触发的路径不刷屏日志**（规则见 U06）。
8. **所有初始化在隐私同意之后进行**；定时线程在业务未解锁时不读任何来源。
9. **业务口径不变**：四桶、费用 breakdown、下钻身份键、游标 v2、`query_expired` 处理全部保持。CCS 只在设置页手动点击后读取。
10. **固定两行筛选栏与玻璃材质、tokens、柔光背景不变。**

## 4. 任务

### U01 时间预设与查询边界（后端 + 日期按钮）

**前端时间预设**

```ts
type RangePreset =
  | { kind: "all" }
  | { kind: "days"; days: 1 | 7 | 14 | 30 }      // 自然日；1 = 当日
  | { kind: "rolling"; hours: 24 }                // 过去 24 小时
  | { kind: "custom"; start: string; end: string | "now" }; // 统计时区本地时刻 "YYYY-MM-DDTHH:MM"；end 为用户选中的最后一分钟（含）
```

**后端参数**

`query_begin` 新增以下参数，与现有的 `days`、`from/to` 一起分成四组，彼此互斥，冲突时返回可读错误：

| 组 | 参数 | 规则 |
| --- | --- | --- |
| 自然日预设 | `days` | 现有逻辑：`[今天-(N-1), 今天]`，另加 `ts ≤ as_of` |
| 自然日区间 | `from` / `to` | 现有逻辑，另加 `ts ≤ as_of` |
| 滚动窗口 | `rolling_hours`（只接受 24） | 时刻模式 `[as_of - 24h, as_of]` |
| 自定义时刻 | `start_at` + (`end_at` 或 `until_now: true`) | 见下 |

自定义时刻的解析规则，全部由后端完成：

1. `start_at`、`end_at` 是统计时区的本地时刻，精确到分钟；`end_at` 表示用户选中的最后一分钟（含）。
2. **整日对齐检测**（在本地时刻上判断）：
   - 若 `start_at` 为 00:00，且 `end_at` 为 23:59 或 `until_now`，转为自然日模式：
     - 有 `end_at` 时为 `[start 日期, end 日期]`；
     - `until_now` 时为 `[start 日期, 今天]`。
   - 否则为时刻模式。
3. **时刻模式的换算**：
   - `start = 本地(start_at)` 换成时刻；
   - `end_exclusive = 本地(end_at) + 1 分钟`，先在本地时刻上加 1 分钟，再换成时刻；
   - `until_now` 时 `end_exclusive` 为空，以 `ts ≤ as_of` 截止；
   - 本地时刻到时刻的换算一律用 jiff 的 `compatible` 规则（夏令时不存在的时刻往后取，重复的时刻取较早的一个）。
4. `start ≥ end_exclusive` 时报错；`start_at > as_of` 时报错（起点在未来）。

另外：
- 现有 `TimeBounds::matches` 增加 `ts ≤ as_of` 判断，自然日模式同样生效。
- 时刻模式下，查询快照不选取任何日汇总桶。若所涉自然日里确有日汇总，报告中附带提示键 `rollups_excluded_for_instant_range`，界面在合并通知里显示：“当前时间范围精确到时刻，只统计请求明细，不含只有日粒度的历史”。

**后端回传**

`QueryHandle` 与 `SummaryReport` 增加 `range`（`all` 时为 `null`）：

```
{ "granularity": "day", "from": "YYYY-MM-DD", "to": "YYYY-MM-DD" }
{ "granularity": "instant",
  "start_local": "YYYY-MM-DDTHH:MM", "end_local": "YYYY-MM-DDTHH:MM",
  "start": RFC3339, "end": RFC3339 }
```

- `end_local` 用于显示：自定义时为用户选中的最后一分钟；24h 与 `until_now` 时为 `as_of` 所在分钟。
- `start`、`end` 是 UTC 时刻，供诊断使用。

**日期按钮**

- 全部时间：显示日历图标，不着色。
- 其余情况显示语义标签，32px 高，沿用现有强调色底：

| 预设 | 按钮标签 |
| --- | --- |
| days 1 | `当日` |
| rolling 24 | `24h` |
| days 7/14/30 | `7d` / `14d` / `30d` |
| 自定义、自然日模式 | `10/1–10/12`；至今为 `10/1 起` |
| 自定义、时刻模式、同一天 | `10/12 09:00–18:00` |
| 自定义、时刻模式、跨天 | `10/11 22:00–10/12 02:00` |
| 自定义、时刻模式、至今 | `10/12 09:00 起` |

- 非当前年或跨年时带年份（沿用 `rangeLabel` 的规则）。
- 标签最大宽 220px，超出省略。
- 悬停提示与可访问名称写完整范围，取自后端 `range`，例如“近 7 天：2026/10/6 – 2026/10/12”“过去 24 小时：10/12 00:31 – 10/13 00:31”；后端返回前只写预设名。

### U03 时区与设置的单一来源、串行保存

- `settings.toml` 新增 `timezone`：合法值为 `local` 或 IANA 名，缺省 `Asia/Shanghai`，非法值拒绝保存；读写走 `settings::update` 事务。
- **迁移旧的 localStorage 键 `tokenscope-tz`：**
  - TOML 已有 `timezone`：以 TOML 为准，删除旧键。
  - 字段缺失且旧键合法：保存到 TOML，成功后删除旧键；失败则保留旧键，本次会话用旧值，并显示非阻断提示。
  - 读取设置失败：旧键合法就用旧键，否则用默认值；不迁移、不删除，显示非阻断提示。
- **启动顺序：** 主应用挂载（已在隐私同意之后）→ 读取设置（复用 `settingsPreload`）得到时区 → 汇总页发起首批查询。时区就绪前不发查询。
- **串行保存（时区与 U06 的读取间隔共用同一机制）：** 每个设置项一个保存队列。

  - 启动读取的结果晚于用户修改到达时，不覆盖用户的修改。
- 视图快照不再包含、也不再写入时区。
- 先写的测试：

### U06 自动读取间隔、变化通知与时间窗口刷新

**设置**

- `settings.toml` 新增 `collect_interval_secs`，可选 `5 / 10 / 30 / 60 / 300 / 600`，界面显示为 5s、10s、30s、1m、5m、10m。缺省 300（与现状一致），其他值拒绝。
- 设置页“数据源”分区放下拉，保存走 U03 的串行保存机制。

**后台采集与查询拆分**

- `report.rs` 新增 `collect_only(opts, trigger) -> CollectOutcome { generation, changed }`：
  - 只做采集与历史库写入（经同一个 `collect_flighted` 单飞协调器），不建查询快照，不聚合；
  - 同时把本轮来源统计（`CollectStats`）连同来源配置身份缓存为“最近一次采集结果”。
- 定时线程改为调用 `collect_only`，不再调用 `report::summary`：
  - 每轮读取当前间隔；
  - 设置保存成功后唤醒线程，按新间隔重新计时；
  - 首轮延迟为 `min(间隔, 30s)`；
  - 间隔从上一轮结束开始计时，不叠加；
  - 业务未解锁或退出中时跳过；
  - 只读原生日志，不读 CCS。
- 每轮结束后，若 `changed` 为真，向前端发事件 `usage-updated { generation }`；否则不发。
- `query_begin` 新增参数 `collect: bool`，缺省 `true`：
  - `true`：启动、手动刷新、筛选变化，行为与现在一致，先采集；
  - `false`：自动刷新使用，直接基于已提交的历史建快照，来源统计用“最近一次采集结果”。若缓存缺失，或来源配置身份不一致，退回 `collect=true` 的行为。
  - `QueryHandle` 已带 `generation`，前端据此判断数据是否已覆盖。

**日志分级**

- 新增 `Trigger { Startup, Manual, Auto }`，沿采集与查询路径传递。
- `Auto` 触发时，上述路径上的 `log::info!` 一律降为 `debug`，只有一处例外：本轮历史库有写入时，保留一条 info 摘要（新增 / 更新条数）。
- warn 与 error 不变。
- 执行者需逐一检查 `report.rs`、`query.rs`、`src-tauri/src/commands.rs`、`src-tauri/src/lib.rs` 中位于采集与查询路径上的 `log::info!`，并在提交说明里列出改动清单。

**前端自动刷新调度（集中在 `useUsageQuery`）**

- **变化通知：**
  - 维护 `latestGeneration`（取收到的 `usage-updated` 与查询句柄中的最大值）。
  - 收到事件后若当前无批次在途，发起一批自动刷新（`collect: false`）；有批次在途时只更新 `latestGeneration`。
  - 任何批次完成时，若其 `handle.generation < latestGeneration`，立即再发一批自动刷新。
- **时间窗口到期：** 汇总页可见时，每 60 秒做一次时钟检查；窗口获得焦点或 `visibilitychange` 变为可见时也立即检查一次（覆盖休眠恢复）。
  - 预设为 `rolling` 时，每次检查都发起自动刷新。
  - 自然日预设或自定义范围包含今天（含“至今”）时，若统计时区的“今天”已不同于本次 `as_of` 的日期，发起自动刷新。
  - 其他范围（全部时间、完全在过去的区间）不因时钟刷新。
- **翻页保护（保证单一查询身份）：** 若用户已对当前会话执行过“加载更多”，或加载更多正在进行，自动刷新不执行。改为在状态区显示“有新数据 · 刷新”（时间窗口到期时显示“时间范围已更新 · 刷新”），点击等同手动刷新。手动刷新与筛选变化不受此限制。
- **隐藏时：** 只置待刷新标记（U04）。
- **合并：** 同一时刻多个触发只产生一批。

**状态与按钮**

- 状态胶囊显示“更新于 HH:MM:SS”，时间取本次查询的 `as_of`，按统计时区显示。刷新中显示“刷新中…”，失败态保持现状。悬停提示写“每 N 秒自动读取”（随设置变化）。
- “刷新”按钮加刷新图标，刷新中显示加载并禁用；保留文字与可访问名称。手动刷新使用 `collect: true`。

**时延口径**

新写入的会话出现在界面上的最长时间，约为“间隔 + 采集耗时 + 查询与渲染耗时”。

**先写的测试**

- Rust：
  1. `collect_interval_secs` 缺省、非法值拒绝、旧 TOML 可读。
  2. 定时线程使用可注入的间隔：改设置后按新间隔触发；采集耗时超过间隔时不并发。
  3. `collect_only` 无变化时 `changed=false`、不发事件；有写入时 `generation` 递增。
  4. `query_begin(collect=false)` 不调用采集；缓存缺失时退回采集。
- 前端：
  1. 事件触发一批 `collect:false` 刷新，筛选与下钻保留。
  2. 批次在途收到更高 `generation`，完成后补发一批；未收到则不补发。
  3. rolling 预设每 60 秒刷新；跨午夜（模拟时钟）后自然日预设刷新；全部时间不因时钟刷新。
  4. `visibilitychange` 可见时立即检查。
  5. 已加载更多时，不刷新，只显示提示；点击提示后发起手动刷新。
  6. 隐藏时只标记。
  7. 胶囊显示“更新于”；刷新中按钮禁用。
