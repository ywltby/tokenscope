# UI 调整计划：时间筛选、汇总页状态与设置页

> 状态：**第三版，待用户确认，未开始实施。** 确认后按 U01 → U06 顺序执行，每项先写能红的测试再改实现。
>
> 修订记录：2026-10-13 第一版；同日第二版按用户新决定（日期按钮显示时间语义、设置页分区）和外部评审意见修订：补全“跟随今天”的结束边界、筛选偏好独立持久化、时区迁移顺序、请求身份与滚动保留，删去不再需要的“全部时间数据跨度”。第三版按用户决定加入真正的“过去 24 小时”滚动窗口与精确到分钟的自定义区间：“当日”与 7d/14d/30d 按自然日，“24h”替换“近2天”。

**Goal:** 让用户从日期按钮上直接看出当前统计的时间范围；修掉时区被旧视图改回、“近 N 天”被存成死日期两个缺陷；收敛汇总页的状态归属；把设置页整理成分区清楚、文案与实现一致的页面。

**Architecture:** 时间范围改为“预设 + 查询入口解析”，后端在冻结 `as_of` 时一次算出边界（自然日或精确时刻）并回传。筛选偏好与视图快照分开保存：偏好决定查什么，快照只在身份完全一致时用于首帧展示。汇总页的查询状态集中到一个组合式函数，必要的请求身份保留；页面切换保留组件与滚动位置。设置页按分区展示。

**Tech Stack:** Vue 3 / Naive UI / Vitest；Rust（`report.rs`、`query.rs`、`settings.rs`）与 Tauri 命令层。

- 与整合计划的关系：本计划由用户 2026-10-13 要求单独开立，与 [剩余任务整合计划](2026-10-11-consolidated-remaining-work.md) 并行。整合计划 N11 中“设置页内部审计文案”一项改由本计划 U05 承担，其余 N10–N13 不变。

## 2. 已核实的问题（证据）

1. **在设置页改了时区，回到汇总页会被改回旧值。** 用临时 Vitest 探针复现（未入库）：时区设为 `UTC`，`view_cache_load` 返回旧快照（`tz: Asia/Shanghai`），挂载后全局时区变回 `Asia/Shanghai`，`localStorage` 被写回旧值，还多发了一次 `query_begin`。直接原因是 `Dashboard.vue` 的 `loadViewCache` 把 `cached.filters.tz` 写进了全局时区 ref；汇总页用 `v-if` 切页，每次回来都会重新挂载并恢复快照，所以每次都会触发。
2. **“近 N 天”被存成固定日期。** 快照的 `filters.range` 只存 `[from, to]`，第二天打开仍是旧区间；“结束日跟随今天”只在点确定的那一刻求值一次。
3. **看不到当前时间范围。** 日期按钮只有图标，范围只在悬停提示里（截图 `qa-artifacts/privacy-consent/normal-light-1280x820.png`）。
4. **日期弹层操作绕。** 弹层里放了两个独立的 `NDatePicker`（弹层套弹层），还有快捷按钮、跟随今天勾选和取消/确定；选一个快捷项要点三次。
5. **汇总页状态分散。** `Dashboard.vue` 脚本约 640 行，九个并发相关状态（`summarySeq`、`eventsSeq`、`refreshEpoch`、`interactionEpoch`、`beginEpoch`、`applyingRestore`、`freshArrived`、`disposed`、`liveFirstPage`）各自承担既有的回归保护。问题不在数量本身，而在“快照恢复”与“用户筛选”共用同一组状态、彼此可以互相改写。
6. **两个页面的切换方式不一致。** 汇总页用 `v-if` 每次重建（丢下钻、恢复旧快照）；设置页用 `KeepAlive`。滚动容器在 `MainApp.vue`，两页共用，切页不保存各自的滚动位置。
7. **通知条各自堆叠。** 汇总页最多七种通知条，与 DESIGN.md §5“多条合并成一条并可展开”不符。
8. **两处小问题。** 下钻提示显示成 `model: xxx`（中文界面混英文类型名）；合计行靠字面量 `"合计"` 判断。
9. **设置页问题：**
   - 一长页七个分组，上千行价格表夹在中间；“Token 显示颜色”排在最前。
   - “缓存”分组写着“缓存是纯优化：任何故障都会自动退回全量扫描”，但该处读取的是 `history.db` 的计数（见 `report.rs` 中 `CacheInfo` 的注释）。历史库是持久事实存储，这句话误导用户。
   - 内部审计编号显示在界面上：CCS 预览说明里有“I-P3-2：保证与可导入逐行闭合”。
   - 来源统计时区的说明里写了 `**这个时区**`，Vue 模板会把星号原样显示出来。
   - 价格候选规则的六行说明直接铺在页面上。
   - 数据源要求“回到汇总页生效”。
10. **时区没有唯一的权威来源。** 时区存在 `localStorage`（`tokenscope-tz`），同时又作为视图快照筛选的一部分被保存和恢复。主题与颜色也存在 `localStorage`，但它们只影响外观；时区影响统计口径，应该和来源配置一起放在 `settings.toml`，只保留一个来源。

## 3. 必须保持的不变量

1. 一次查询只在入口取一次 `as_of` 并冻结（SF05）。自然日预设 = 统计时区下 `[今天-(N-1), 今天]` 的闭区间；24h = `[as_of - 24 小时, as_of]`；自定义 = 统计时区本地时刻换算出的 `[start, end)`，“至今”以 `as_of` 为终点。所有边界都**不含未来**。前端不自己计算查询用的边界。
2. 日期按钮的提示与可访问名称里的具体日期与时刻，取自本次查询冻结的结果（后端回传），与汇总数字同源。
3. 筛选偏好（来源、维度、时间预设、日粒度参与方式、下钻）独立持久化，是决定“查什么”的唯一依据；视图快照只在其完整身份与当前偏好和时区**逐项相等**时用于首帧展示，绝不反向改写偏好或时区。
4. 日汇总只有日粒度：范围不按整日对齐时，日汇总不参与、不按比例估算，并在所涉日期确有日汇总时明确提示；整日对齐的自定义范围按自然日处理，日汇总照常参与。
5. 时区只有一个持久来源，就是 `settings.toml`。首次查询必须在时区初始化完成之后发起。
6. 所有初始化仍在隐私同意之后（主应用挂载之后）进行。
7. 业务口径不变：四桶、费用 breakdown、下钻身份键、游标 v2、`query_expired` 处理全部保持。
8. 固定两行的筛选栏形态，以及玻璃材质、tokens、柔光背景都不变。
9. 测试密闭：新测试不读写真实 `~/.tokenscope`。

## 4. 任务

### U01 时间预设、查询边界与日期按钮语义（问题 2、3）

**时间状态**

前端时间状态改为预设：

```ts
{ kind: "all" }
| { kind: "days", days: 1 | 7 | 14 | 30 }   // 自然日；1 即“当日”
| { kind: "rolling", hours: 24 }            // 过去 24 小时
| { kind: "custom", start, end }            // 统计时区本地时刻，精确到分钟；end 可为 "now"
```

**后端时间边界**

在 `TimeBounds` 现有的“自然日边界”之外，新增“时刻边界” `[start, end)`。查询参数分为四组，彼此互斥，冲突时报错：

| 组 | 参数 | 含义 |
| --- | --- | --- |
| 自然日预设 | `days` | 现有逻辑不变：`[今天-(N-1), 今天]` |
| 自然日区间 | `from` / `to` | 现有逻辑不变 |
| 滚动窗口 | 新增 `rolling_hours` | `[as_of - N 小时, as_of]` |
| 自定义时刻 | 新增 `start_at` / `end_at` / `until_now` | 统计时区的本地时刻 `YYYY-MM-DDTHH:MM`；`end_at` 为开区间终点；`until_now` 表示终点为 `as_of`，与 `end_at` 互斥 |

自定义时刻的补充规则：

- `start_at >= end_at` 时报错。
- 夏令时下不存在或重复的本地时刻，按 jiff 的 `compatible` 规则换算，并写测试覆盖。
- **整日对齐时归一为自然日。** 起点是 00:00，且终点是 00:00 或 `until_now` 时，后端把它换成自然日区间：起点日到“终点前一天”，`until_now` 时到今天。这样整天的自定义范围与快捷项口径一致，日汇总照常参与。
- 所有边界都不含未来记录。
- 旧的“结束日跟随今天”由 `start_at` 为 00:00 加 `until_now` 表达，`since` 预设不再单独存在。

**日汇总与时刻边界**

- CCS 日汇总只有日粒度，所以“24h”和不按整日对齐的自定义范围只统计请求明细，日汇总不参与，也不按比例估算。
- 只有当所涉自然日里确实存在日汇总时，才在合并通知里提示：“当前时间范围精确到时刻，只统计请求明细，不含只有日粒度的历史”。

**后端回传**

`QueryHandle` 与 `SummaryReport` 增加本次冻结后的范围，`all` 时为空：

```
range: { granularity: "day", from, to } | { granularity: "instant", start, end }
```

其中 `start` / `end` 为统计时区下的 RFC 3339 时刻。

**日期按钮**

全部时间时显示日历图标，不着色。选了时间后，图标换成语义标签，保持 32px 高、`--ts-fill` 底，有范围时沿用强调色底：

| 预设 | 按钮标签 |
| --- | --- |
| 当日 | `当日` |
| 过去 24 小时 | `24h` |
| 7 / 14 / 30 个自然日 | `7d` / `14d` / `30d` |
| 自定义（整日） | `10/1–10/12` |
| 自定义（整日、至今） | `10/1 起` |
| 自定义（带时刻、同一天） | `10/12 09:00–18:00` |
| 自定义（带时刻、跨天） | `10/11 22:00–10/12 02:00` |
| 自定义（带时刻、至今） | `10/12 09:00 起` |

- 非当前年或跨年时带年份，沿用 `rangeLabel` 的规则。
- 标签最大宽度 220px，超出省略；完整内容在悬停提示里。
- 悬停提示与可访问名称写完整范围，取自后端回传的值，例如“近 7 天：2026/10/6 – 2026/10/12”“过去 24 小时：10/12 00:31 – 10/13 00:31”。查询返回前只写预设名。

**文档与快照**

- 同步更新 DESIGN.md §4 的布局示意和 §5 的筛选栏条目（有筛选时日期按钮显示语义标签；仍不显示时区和副标题）。
- 视图快照版本升至 v12，v11 及更早的快照一律不用。

**先写的测试**

- Rust：
  - 四组参数各自冻结的边界正确，跨日界与“现在”由 `as_of` 决定；
  - 四组参数两两冲突时报错，`start_at >= end_at` 报错；
  - 24h 窗口只包含 `as_of` 前 24 小时内的事件，跨两个自然日时按天分组正确；
  - 整日对齐的自定义时刻与等价的自然日区间结果完全相同（含日汇总）；
  - 不对齐时日汇总不参与，且提示只在所涉日期确有日汇总时出现；
  - 夏令时时区（如 `America/New_York`）下不存在与重复的本地时刻；
  - 所有组都不含未来记录。
- 前端：
  - 选择“7d”后把模拟时钟推进一天再挂载，`query_begin` 收到 `days: 7`，不是旧日期；
  - “24h”每次查询都发 `rolling_hours: 24`；
  - 上表各形态的按钮标签与可访问名称正确；
  - 全部时间显示图标且不着色。

### U03 时区单一来源与迁移（问题 1、10）

**存储**

`settings.toml` 新增字段 `timezone`，合法值为 `local` 或 IANA 名，缺省 `Asia/Shanghai`；读写走 `settings::update` 事务，非法值拒绝保存。

**迁移优先级**

- TOML 中已有 `timezone` 时以它为准，旧 `localStorage` 键直接删除。
- 只有字段缺失、且旧键合法时才迁移：后端保存成功后再删除旧键；保存失败则保留旧键，本次会话沿用旧值，并显示非阻断提示。
- 读取失败时：旧键合法就用旧键，否则用默认值；不迁移，不删除旧键，并显示非阻断提示。

**启动顺序**

主应用挂载（已在隐私同意之后）→ 读取设置得到时区（复用现有设置预读）→ 汇总页发起首批查询。时区就绪前不发查询。

**设置页修改**

- 每次保存带递增序号。
- 较早的保存响应晚到时，不覆盖较新的选择。
- 保存失败只在“没有更新的待完成保存”时回滚显示值，并显示局部错误。
- 启动读取晚于用户修改返回时，不覆盖用户的修改。

**快照**

快照不再写时区；快照时区与当前时区不一致时不使用该快照。

**先写的测试**

- 把这次的探针改成正式回归：时区为 UTC、快照为 Asia/Shanghai，挂载后时区仍为 UTC，只发一批查询，且 `tz: "UTC"`。
- 迁移四种分支：TOML 有值、字段缺失且旧键合法、保存失败、读取失败。
- 连续两次保存时第一次响应晚到；保存失败时已有更新的待完成保存。
- Rust：缺省值、非法值拒绝保存、旧 settings.toml 无该字段时读取正常。

### U04 汇总页状态归属、切页保留与通知合并（问题 5、6、7、8）

**状态归属**

- 新增 `composables/useUsageQuery.ts`，集中持有查询状态。
- **保留必要的请求身份**：主查询批次、同一 `query_id` 内的明细（下钻）请求序号、分页锚点身份、局部重试的作用范围、快照代次。只删除被新测试证明多余的守卫，不预先承诺删除数量。
- 快照恢复只填充展示数据并标记 stale，不触发筛选 watcher，不写任何偏好。

**筛选偏好持久化**

- 来源、维度、时间预设、日粒度参与方式、下钻存入 `localStorage` 的 `tokenscope-view-filters`，属于本机视图便利，与主题、颜色同类。启动时同步读取。
- 非法值回退为默认值：全部来源、按时间、全部时间、自动参与、无下钻。
- 快照只在“偏好 + 时区”逐项相等时用于首帧，其他情况直接正常查询。

**切页保留**

- `MainApp.vue` 中汇总页改为 `KeepAlive`。
- 滚动容器离开某页时记录该页的 `scrollTop`，进入时恢复。
- 汇总页隐藏期间，时区变化、`refreshKey`、设置保存都只标记“待刷新”，不发查询（KeepAlive 停用期间 watcher 仍会运行，必须显式拦截）。
- 回到汇总页恰好发起一批后台刷新，保留筛选、下钻与滚动位置。

**通知合并**

- 合并为一条通知，显示最高严重级别与条数；展开后逐条列出。
- 每条保留原有动作：重试、去设置、只看请求明细、恢复自动参与。

**小问题**

- 下钻提示改用中文类型名：日期、模型、项目。
- 合计行改由 `UsageTable` 发出单独的事件，汇总页不再比较字面量 `"合计"`。

**先写的测试**

- 同一 `query_id` 内连续切换下钻、旧明细晚到时被丢弃。
- 分页响应晚于筛选变化到达时不拼接。
- 局部重试只重发失败的一侧。
- 快照与新数据不混代保存。
- 切到设置再回来：筛选、下钻、滚动位置保留，只发一批查询。
- 隐藏期间多次触发只合并成一批。
- 三类问题同时存在时只渲染一条通知，展开后三条且动作可用。
