# 统计口径说明（stats semantics）

> 本文件是 TokenScope 统计口径的**权威说明**（计划 B1/B2 交付物，2026-10-05 建立）。
> 改动解析、去重或计价语义时必须先更新本文件并同步失效缓存（`cache.rs` 的
> `SCHEMA_VERSION`），再改实现。每个结论注明证据来源与适用日志版本。

## 1. 请求单位

「请求数」= 纳入统计的去重用量事件数（按日志口径），**不等于**用户提问数，
也不等于底层 API 请求次数（适配器可能在一次提问中产生多条用量记录，也可能
合并）。UI 中展示为「请求」；各适配器的纳入/排除规则见下文，排除项均有
独立计数（`bad_lines` / `skipped_*` / `duplicates_dropped`），在来源采集统计中可见。

**纳入范围（2026-10-10，H02）**：统计对象是各代理**全部**可读到的有效用量
事件——不区分主链与子代理、不按目录层级或来源通道排除。唯一排除项是各适配器
明确列举的合成行、无用量行与畸形行，且逐项计数可见。来源发现的默认范围：
Claude = `~/.claude/projects/**/*.jsonl` 全层级；Codex =
`${CODEX_HOME:-~/.codex}` 下的 `sessions/**/*.jsonl` 与
`archived_sessions/**/*.jsonl`（显式自定义根时只在选定目录内递归，且不把
CLI 的 `history.jsonl` 当作 rollout）。

## 2. Token 桶（互斥四桶）

内部存储、IPC 与计费保留四个互斥桶：**非缓存输入 / 输出 / 缓存写 / 缓存读**。
契约测试：`tests/token_bucket_contract.rs`。

界面中所有应用的「输入」统一显示总输入，即非缓存输入 + 缓存写 + 缓存读。
缓存写、缓存命中作为输入的子项独立展示；总 token = 展示输入 + 输出，不能重复加缓存。
缓存命中率 = 缓存读 / 总输入。图表四项并列展示，不做相加堆叠；汇总比例条仅分输入与输出。
计费仍按互斥桶分别使用各自单价：例如 3 token 按普通输入价、2,057 token 按缓存写入价，
不合并计费。费用明细的「输入（扣除缓存）」明确标出普通输入计费量。
此次只改变展示，原始日志、缓存和费用计算不变，无需升级缓存版本。

### 2.1 Claude Code（`~/.claude/projects/**/*.jsonl`）

Anthropic Messages API 的 usage 四字段本身就是互斥桶，逐一映射：

| 日志字段 | 桶 | 说明 |
| --- | --- | --- |
| `usage.input_tokens` | 非缓存输入 | Anthropic 语义：不含 cache_read/cache_write |
| `usage.output_tokens` | 输出 | 含 reasoning（不单列） |
| `usage.cache_creation_input_tokens` | 缓存写 | 计 1.25× 价格 |
| `usage.cache_read_input_tokens` | 缓存读 | 计 0.1× 价格 |

只取 `type=assistant` 且含 `message.usage` 的行；**子代理（`isSidechain`）
用量自 2026-10-10（H02）起一并纳入**——子代理请求同样是真实消耗，主/子代理
关系、层级与昵称都不入库、不增加界面分类（计划 §2 不变量 1）。sidechain 行的
`cwd` 属另一执行上下文，**不参与**本会话项目根的推进（身份隔离，见 §3.4），
仅其用量入账。合成行（`model == "<synthetic>"`）仍排除并计数。
**`isApiErrorMessage` 不在排除口径内**（代码未读取该字段）：API 错误行
通常不带 usage，经"缺 usage"路径跳过；若未来出现带 usage 的错误行会
入账——口径变更需先行确认并更新本文件。去重身份 =
`(session_id, message.id)`，保时间戳最晚一条（流式重发取终值）。

### 2.2 Codex（`~/.codex/sessions/**/*.jsonl`，rollout 格式）

只取 `event_msg/token_count` 的 `info.last_token_usage`；`token_usage_record`
是线程级**累计回显**（含 `response_id`/`turn_id` 但值非单请求口径），一律
忽略并计数（双计防线）。

`token_count` 也用于额度状态通知：当 `info` 为空且 `rate_limits` 为对象时，
校验时间戳后跳过，不计坏行、不产生请求或费用。`info` 存在但缺少
`last_token_usage` 的记录仍计坏行；额度状态不能用于推算 token 用量。

**字段语义（R02 已查证，2026-10-05）**：OpenAI Responses API 的
`input_tokens` 是**总量桶**，`input_tokens_details.cached_tokens` 与
`cache_write_tokens` 均为其子集。官方文档示例：
`input_tokens=15000 = cached_tokens 12000 + cache_write_tokens 3000 + 0 未缓存`
（[prompt-caching 指南](https://developers.openai.com/api/docs/guides/prompt-caching)）。

归一化（Codex CLI **≥ 0.145.0** 透传 `cache_write_input_tokens`）：

| 日志字段 | 桶 |
| --- | --- |
| `input_tokens − cached_input_tokens − cache_write_input_tokens` | 非缓存输入 |
| `output_tokens` | 输出 |
| `cache_write_input_tokens` | 缓存写（GPT-5.6+ 计 1.25× 价格） |
| `cached_input_tokens` | 缓存读（计 0.1× 价格） |

守恒式：`非缓存输入+输出+缓存写+缓存读 == input_tokens+output_tokens == total_tokens`。

- **旧版日志（< 0.145.0）**：无 cache_write 字段（serde 缺省 0），退化为
  `input = raw − cached`，与 M2 以来的历史行为一致。
- **订阅（ChatGPT）流**：服务端当前恒返 `cache_write_input_tokens = 0`
 （[issue #32479](https://github.com/openai/codex/issues/32479) 评论区，
  OpenAI 成员确认 client 侧已修、服务端置零是独立问题）→ 订阅用户的
  缓存写桶恒为 0 属**数据源现状**，不是本工具丢数。
- **未知字段组合**：`cached + cache_write > input` 的行无法用已查证语义
  解释（例如第三方 provider 的自定义映射），按**坏行计数**不入账，不猜测。

校验式：`total == input + output`（本机 47 文件全量成立，M2 实测）。

### 2.1 异常 token 算术（SF08）

- 单事件的四桶总数与 prompt 计价基数（input + cache_write + cache_read）
  必须在 u64 内**可表示**：codex 行的零值判断逐字段比较（不做无谓加法）、
  守恒校验（total = input + output；cached + cache_write ≤ input）与
  Claude 四字段事件的同一边界校验全部**受检**——异常行计 bad_lines 并
  跳过，继续处理后续行；不得回绕、不得饱和截断成"正常"数据。
- 聚合层桶累计、分组请求数、未知桶与总计全部受检：一次事件的更新先在
  临时值上全部成功再提交；多个**各自合法**的事件累计溢出时返回明确的
  查询错误（保留 UI 旧数据/重试），不跳过"最后一个"制造不确定统计。
- 金额累计出现非有限值同样报错，不序列化成正常空值；请求级溢出诊断
  （pricing 层 overflow）语义不变。
- 缓存恢复的事件与两适配器解析的事件经过**同一**校验边界；旧缓存中
  不合法事件不得绕过（恢复时拒绝并计 bad_lines）；解析语义变化时
  递增缓存 schema 版本整体重建（源日志永不删除）。

### 2.2 跨适配器来源目录重叠（SF09）

- 所有**启用**来源的有效目录（显式配置或工具默认根）规范化后两两检查
  **相同或嵌套**关系：保存时（设置事务锁内）与采集时都拒绝，错误列出
  冲突目录、影响来源与恢复方法（改目录或停用其一）；禁用来源不参与
  检查，用户可借停用恢复配置。
- 校验与 agent 筛选无关：「全部来源」与「仅某来源」对同一无效启用
  配置一致报错；`source_status`/设置读取仍返回配置与诊断，用户能
  修正，不因拒绝采集而进不去设置页。
- 发现阶段同一规范化文件被不同 adapter 认领 → 明确返回归属冲突；
  **移除「先发现者得」**的跨 adapter 默认。不重复计数、不污染另一
  adapter 缓存的不变量保留；独立来源的解析与去重规则不变。

## 3. 去重（dedupe）

全局去重（M4 起上移，`src/dedupe.rs`），在缓存合并之后、聚合之前执行，
保证无缓存/缓存命中/重建三路径数字一致。

### 3.1 Claude Code

同 `(session_id, message.id)` 保留时间戳最晚一条（流式增量重发，终值即
最终 usage）；时间戳相同保行序靠后。**无已知误伤**：`message.id` 唯一
标识一次响应。

### 3.2 Codex

同 `(session_id, model, 非缓存输入, 输出, 缓存写, 缓存读)` 保留**首条**
（归一化字段可重建 raw 五元组；B2 起键含 model）。

**为什么要去重**：同一请求的 `last_token_usage` 会被原样重发（M2 实测
2,897 组 / 多余 3,012 行，多数 ×2：流式结束与回合结束各发一次；数值逐字
相同、时间戳不同、行距 1~10+ 行、`info` 无可区分字段、全部在文件内部）。
不去重会把每个请求计成约 2 倍（初版实现即因此与 cc-switch 呈精确 2 倍差）。

**已知限制（R01，保守规则的代价）**：`token_count` 事件本身**没有**请求
身份（`info` 无 id 字段，M2 逐字段核对）；同一会话内**同模型**且四桶数值
完全相同的两个真实请求，会被保守合并为一条。当前证据下无法在不误放重播
的前提下区分这两者（时间戳不能入键——重播的时间戳本就不同）。B2 已把
model 纳入键：**跨模型**的同用量请求不再误合并；重播必然同模型（同一
`turn_context`），防线不变。同模型同用量的合并误伤面（数值恰好相等的
探活级请求）远小于重播误伤面（不去重则整体 ×2），故保留保守规则。
**替代方案（未立项）**：改用 `token_usage_record` 的 `response_id` +
线程累计值差分推导单请求用量，可获得精确身份，但需重写采集口径并重新
对账，且依赖 `token_usage_record` 在各日志版本中的可靠性——待有真实
多版本日志可对照时另行验证。

### 3.3 契约测试

`src/dedupe.rs`：重播保首条、跨批次/跨日仍去重、agent 间隔离。
`tests/e2e_events_range.rs` 等端到端测试保证去重与汇总/明细同源。
`tests/all_usage_sources.rs`（H02）：子代理用量并入、同请求跨文件取终值、
多根发现与归档目录、非 rollout 文件不纳入、可证实的跨来源身份。

### 3.3.1 跨来源请求身份（H02/H05）

原生采集与 CCS 导入共享同一份**可证实**身份规则（`UsageEvent::native_identity`）：

- Claude：`claude-message` = `<session_id>|<message.id>`——上游稳定标识，
  原生事件与 CCS 请求行都能解析出同一取值，因此同一请求在两侧被绑定到同一条
  历史事件（`event_aliases`），不重复计费；
- Codex：rollout 的 `token_count` **不带**请求标识，因此该来源没有跨来源身份
  ——导入侧不得猜测身份，只按来源记录键与 §3.2 的保守重播规则处理；
- 身份不足（缺 session / 缺 message.id）时返回 `None`，事件仍入账，但不参与
  跨来源合并。

### 3.4 项目身份（C2/R03；2026-10-09 阶段 A + 阶段 B 修订）

- **统一 key**：项目身份 = source 层归一化的绝对路径（Windows 反斜杠统一为
  `/`、盘符大写、非根去尾随分隔符；根路径与 UNC 保留主机/共享语义；`file://`
  按 URI 解析并只做一次百分号解码）。归一化不访问文件系统、不折叠符号链接/
  junction/worktree 或目录别名；不可安全解释的输入（相对路径、`C:foo`、
  非 file scheme、非法百分号编码、`.`/`..` 组件）判为「不可用」并走兜底。
- **归属规则（B01 定稿，两侧一致）**：按**项目根**归并——会话从 `/test` 起步时，
  进入 `/test/123` 或更深目录仍归 `/test`；工作目录一旦**越出当前根**
  （如 `/test` → `/bee`），该目录即成为新项目，其子目录（`/bee/123`）同属
  新项目。判定用归一化路径的**分量边界前缀**比较（不折叠大小写、不做文件系统
  访问、不推断仓库根）；回到先前的其他目录同样按"越界即新根"处理。
- **Claude**：按行序推进项目根（非 sidechain 行的有效顶层 `cwd`；sidechain
  记录不参与身份）。同 session 内子目录漂移不改变根，越出根才切换。完全没有
  可信 cwd 时回落 `~/.claude.json` 的 projects **正向编码**（每个非 ASCII 字母
  数字字符 → `-`）唯一命中的真实路径；冲突（同一 slug 多个不同路径）或映射
  缺失/损坏时保持 slug 独立身份——不反向解码、不选第一个、不按前缀猜测。
- **Codex**：`session_meta` 重置项目根（新会话不继承上一会话目录），有效
  `turn_context.cwd` 按同一规则推进；空/无效 cwd 不清掉同会话已知根；完全
  没有可信 cwd 时记 `(未知)`。
- **B01 证据（`docs/research/2026-10-09-session-cwd-semantics.md`）**：Codex 的
  `turn_context.cwd` 是**轮级工作目录**（本机 905/905 带 cwd，66 个 session 中
  1 个出现过切换）；Claude 的顶层 `cwd` 是**行级状态快照**（每行都带，20 个
  session 中 1 个出现非 sidechain 漂移，形态为"短暂进入子目录再返回"，另 3 个
  多值 session 全部由 sidechain 行构成）。两侧语义不同，不能共用同一个
  「会话目录」解释。
- **事件字段（B02）**：`project` = 已决归属 key（项目根）；`session_initial_cwd`
  = 会话首个有效 cwd；`event_cwd` = 该请求作用域内最近观察到的结构化 cwd
  （保留子目录细节，用于排查与后续规则演进）。三者贯通缓存与 IPC。
- **展示名（`Group.label`）= 路径末段**，完整身份保留下钻匹配。
- **跨工具合并**：同一路径的 Claude 与 Codex 会话归入同一项目、一次聚合；
  仅展示名相同（Claude 只有 slug、或路径不同）**不合并**
  （`tests/project_alias_cross_agent.rs`、`tests/project_path_drilldown.rs`）。
- **失效**：Claude 项目映射的内容与状态构成解析上下文修订（缓存
  `files.context_rev` 与采集复用键都据此区分）——配置变化后新查询重新解析，
  已建立的查询会话继续使用旧冻结快照；解析版本 9（项目根归并）、界面快照
  版本 8，旧分组/旧下钻 key 读取时忽略。
- **不做的事**：worktree、符号链接与别名目录不归并；`cd` 到当前根之外算切换
  项目、进入子目录不算——不需要"仓库根"推断，也不需要父子目录自动归并。

## 3.5 分页游标与查询快照（D1/Task 2；SF04 扩展）

- 明细游标 = **完整精度 UTC 时间戳 + record_id** 的不透明串
 （`EventRow.cursor`），前端原样回传、不得从展示字符串反解；
- `(ts, record_id)` 元组严格小于语义，同秒亚秒不丢行、空 record_id
  靠亚秒决序；`total` 恒为过滤后全量（不含游标截断）。
- **SF04 查询快照**：`query_begin` 创建短生命周期不可变快照——一次
  采集的事件集、价格表与修订号、SF05 冻结的 as_of/时区/范围、来源
  身份全部冻结；`query_summary` / `query_events` 显式携带 query_id，
  翻页不重新采集、不重新排序、不重新编号、不换价格。
- **游标 v2**：`{v:2, qid, mfp, dfp, ts, rid, seq}` 绑定 query_id、
  主查询指纹、下钻过滤指纹与快照内唯一行位置。版本不符（含 v1 旧
  游标）、会话不存在/被淘汰/进程重启、query_id 或指纹不匹配、行
  位置不存在 → 一律**结构化拒绝**（`query_expired` / 游标非法），
  允许刷新重建，绝不静默换第一页或新采集结果。
- **查询身份跨启动唯一（RC01）**：`query_id` 由**每次进程启动从系统
  随机源取的 128 位命名空间**（32 位十六进制）与进程内单调计数、
  采集 generation 组合而成，形如 `q<ns>-<n>-g<gen>`。时间戳、PID、
  纯进程内计数（单独或简单拼接）都**不构成**跨启动唯一性——重启后
  计数归零会重新产生 `q0-g0`，使旧游标在新进程中被错误接受并续到
  新采集结果（2026-10-08 复核 RC01 已复现）。随机源初始化失败时
  **明确返回查询错误**，不回退为时间/PID；进程内计数溢出同样显式
  拒绝，不复用旧身份。游标仍是**不透明身份串**，`v2` 线格式不变
  （仅 qid 内容变化，不触发事件缓存重建）。
- 快照会话有数量/内存预算与空闲 TTL（具名常量）：优先淘汰闲置旧
  会话，单个快照超出总预算时明确报错，不截断事件集。
- **保留字节预算（RC05）**：`MAX_RETAINED_QUERY_BYTES` = 256 MiB 约束
  的是**查询子系统保留的数据**，记账对象是每个会话**完整可达的保留对象
  图**——事件 `Vec` 分配与每个事件的四个 `String`（model/session_id/
  project/record_id，按容量计）、逐源统计、采集诊断字符串、价格表的
  候选/嵌套分段/峰谷规则与索引、快照行索引 `Vec`、查询身份/时区/主指纹
  元数据；全部受检加法，溢出显式报错。
  - **不由筛选命中行数代替**：2026-10-08 复核复现
    `filtered_rows=0 retained_events=5`——零命中行的查询仍保留整份采集
    事件与价格表，旧实现按 `rows.len()` 记账等于不计（旧的行数上限
    `MAX_TOTAL_SNAPSHOT_EVENTS` 及其"约 300 MB 上界"的注释结论不成立，
    已移除）。
  - 共享对象（同一份采集快照/价格表）在不同会话中**允许重复记账**，
    换取简单且保守的上界；额度由随快照**最后一个 `Arc`** 释放的
    reservation 持有，因此**被淘汰但仍被读取者持有的快照继续占账**，
    直到读取结束。
  - 额度不足时优先淘汰**仅注册表持有**的会话（淘汰即真正腾出额度），
    没有可回收会话时**明确失败**（错误说明保留量、本次需求量、已保留量
    与预算），不超预算接受，也不为一次注定失败的准入牺牲活跃会话。单个
    快照自身超预算在淘汰前直接拒绝，已有会话与其事件集不受影响、不被截断。
  - **建议必须与保留量一致**：采集事件整份随会话保留，时间范围只是采集
    **之后**的过滤（`collection_key` 不含 from/to/days），因此缩小时间
    范围**不会**减少保留字节——准入错误不得把"缩小时间范围"当作有效建议，
    只能给出真正会改变保留量或等待释放的动作（减少并发查询会话、等待闲置
    会话按 TTL 回收、在设置中停用暂不采集的来源目录）。
  - **准入的原子性位置**：占额度在**额度锁**（`quota()`）内一次完成
    （`used + bytes` 受检且不超上限才提交），注册表锁只负责会话身份与容量
    淘汰；被淘汰项在**锁外**丢弃，因为其 `Drop` 要取额度锁——若在注册表锁
    内丢弃会形成额度锁/注册表锁的反序。两者职责不同，不因此放松准入。
  - **保守系数与不覆盖项**：每次堆分配额外计入 `ALLOC_OVERHEAD = 16`
    字节（分配器元数据 + 对齐填充），`HashMap` 每桶额外计入
    `MAP_BUCKET_OVERHEAD = 8` 字节；字符串按 `capacity()` 而非 `len()` 计。
    这些系数是**保守估计**，不覆盖：分配器自身的分池/碎片行为、SQLite
    连接与页缓存、价格索引文件缓冲、Tauri/WebView2 与前端持有的数据、
    以及下面的建表期间临时峰值。叶子助手（容量×元素大小、字符串容量、
    HashMap 桶）全部使用受检乘加，溢出显式报错——**不用 saturating 夹取**，
    因为夹取会把一次超大的保留量报成预算放得下的假小值。
  - **临时峰值另行量测**（不由保留预算覆盖）：
    `cargo test --offline --test query_memory_budget build_peak_is_measured_separately_from_retained_charge -- --nocapture`
    在本测试二进制内挂计数式全局分配器，量 400 条合成事件的
    `begin_query` 窗口（2026-10-08 实测）：保留记账 **102,390 B**，窗口内
    进程存活字节峰值相对起点 **+230,651 B**，窗口结束时仍存活 **+77,382 B**
    （峰值/仍存活 ≈ 3.0）。即同一查询在建立期间的瞬时占用约为最终保留量
    的 2–3 倍，这部分**不在** 256 MiB 保留预算的保证范围内，文档与错误
    信息都不得声称它被同一数值限制。
  - **边界（不夸大）**：本预算**不宣称**整个进程 RSS、分配器缓存、或
    采集/建表/解析期间的**临时峰值**被同一数值限制；临时峰值另行量测，
    不作为"已由保留预算覆盖"计入。
- 主筛选（来源/时间/时区）变化必须新建查询；下钻（模型/项目/日）
  在同一快照内应用固定过滤；手动刷新总是新建查询并切换批次。
- **前端分页资格（RC02）**：前端只有在本进程内**成功取到当前后端会话
  的首页**之后，才把该会话记为 live 并允许续页。磁盘恢复的旧视图只作
  stale 展示——它的末行游标属于保存时的旧 `query_id`，**不赋予** live
  身份，恢复期间"加载更多"禁用并说明原因（刷新完成后可继续），不得
  静默失败或把旧游标发往新会话。新批次的首页失败后同样没有分页资格。
- **错误恢复分级（RC02）**：会话级失败（`query_begin` 失败、结构化
  `query_expired`、会话被淘汰、外会话游标）→ 错误条的重试动作建立
  **一个新批次**（一次 `query_begin`，汇总与首页共享同一新 `query_id`，
  汇总/首页两侧重试都收敛到这一次 begin）；普通当前会话请求失败 → 仅
  局部重试失败的那一侧。失败过的 `begin` Promise 不得复用（否则重试
  永远重发同一失败请求）；新批次仍失败可再次重试，不自动无限重试。
  错误类别按结构化 code 判定（`frontend/src/lib/queryError.ts` 单一
  来源），**不**把所有失败都当成 `query_expired`。
- 前端视图快照版本随 DTO 升级：磁盘旧视图可作 stale 展示，但其
  游标不得在重启后继续追加（后端游标 v2 校验兜底 + 前端 live 首页
  门槛）。

## 3.6 时间范围与今天基准（SF05）

- **预设近 N 天 = 统计时区下 `[起始自然日, 今天]` 的自然日闭区间**，
  不含未来日期。事件归属只做一次统计时区落日转换（UTC 存储原样，
  比较在转换后的本地日历日上完成）。
- **一次查询只解析一次 today**：`summary` / `list_events` / 后续查询
  快照（SF04）各自在入口解析一次 as_of，过滤全程使用冻结值，不在
  事件循环或翻页中重新取 now；跨午夜属于**下一次查询**的语义。
- `days = 0` 按既有约定归一为 1；超大 days 使日期减法超界时返回
  可读错误（"起始日期超出可表示范围"），禁止 expect/panic。
- 用户显式 `from/to` 区间（含未来日期）与「全部时间」**不得**被
  擅自截断到今天；`from > to` 报错；days 与 from/to 互斥不变。
- 前端快捷项/确认/标签每次操作只读取一次 today，两端日期由同一
  值派生；`formatted-value`（yyyy-MM-dd 字符串）接口保持不变。

## 4. 费用（估算）

- 费用为**估算**：模型前缀匹配价格表（外置 pricing.toml > models.dev >
  OpenRouter；**无编译期内置表**——未收录模型始终 unknown），按四桶
  分别计价后求和。前缀命中不等于实际供应商账单（第三方路由、折扣、
  订阅额度、税费均未覆盖）；UI 标注「估算」。首次启动无 models.dev
  快照时，全局横幅提示联网同步（Task 3）；本地快照是离线缓存。
- **缺价格 ≠ 零价格**：完全无价格的模型，事件费用不计入且 tokens 进入
  `unknown_tokens`，`unknown_pricing = true`（表格 `†` 标记）。
- **部分计价（B3/Task 5）**：价格分项未知（快照缺键/OpenRouter 缺价）
  时，该分项按未知处理；**仅当该分项实际产生 token（> 0）才标记
  `complete = false`**——零 token 的未知分项不打 †；未知 token 数单列
  "未知†"列。
- **缓存失败（不变量 9）**：缓存任何故障降级全量扫描并告警；解析版本
  不符自动清库；测试密闭（不触碰真实 `~/.tokenscope`）。
- 价格快照与外置文件的来源、条数、同步时间在设置页可见。
- **候选匹配与最高费用（Task 2A + 2026-10-10 等价键）**：匹配键取模型标识
  最后一个 `/` 之后的末段，先按**等价规则**归一——ASCII 转小写并删除
  `-` `.` `_`（`claude-opus-5-5` / `claude-opus-5.5` / `Claude_Opus_5_5` 同为
  `claudeopus55`；`/` 渠道结构与 `:` 变体结构保留语义，渠道名等元数据展示
  仍用原文）。同一等价键可对应多个渠道/来源候选（互不覆盖）；匹配分阶段
  回退：完整等价匹配（含 variant）→ 完整匹配 variant 回退（显式标记）→
  **边界前缀**匹配 → 前缀 + variant 回退。前缀只能在查询基名的**分隔符边界**
  截断（记录分隔符对应的等价键偏移）：`opus55-20261010` 可回退到 `opus55`，
  而 `opus550`、`gpt-500` 不含边界，不得命中更短的条目；压缩后为空的基名
  （`-._`、`provider/---`）按未收录处理，显式空变体（`opus55:`）不等同于
  基础模型。对每个候选按**本次请求条件**（prompt token、事件时间）计价后取
  **总费用最高者**作为保守估算；费用并列按来源优先级（外置 > models.dev >
  OpenRouter）> 完整匹配 > 前缀更长（按等价键长度）> 原始键打破。禁止从
  不同候选拼单价；breakdown 的 `match_mode` 与 `candidate_count` 记录匹配
  方式与候选数。
- **模型身份分组与展示名（2026-10-10）**：按模型图表与聚合列表使用**等价
  身份键**分组（`Group.key`）——同一模型的多种写法合并为一行，跨应用也合并；
  不同版本（日期后缀）、不同变体（`:free` / `:thinking`）与无分隔符的相似名
  保持独立身份：即使它们前缀回退命中同一价格，也不合并用量。展示名
  （`Group.label`）优先取该等价 ID 命中的**可信 models.dev 模型名**（模型级
  `name`；provider 名不作兜底，v1–v3 旧快照的名称在加载时清空），否则退回该
  组原始模型名的稳定代表写法（绝不展示压缩键）；同名不同 ID 不合并。下钻按
  同一身份规则匹配（传身份键或原始写法都能命中），请求明细仍展示原始模型名；
  每个请求按自身时间/分段/原始名称计价，分组费用是这些请求费用之和。
- **价格索引与费用视图失效（2026-10-10）**：索引版本 **v9**，来源签名同时
  携带**匹配规则版本**（`rules:v9`）——规则升级后即使来源字节完全不变，也会
  重建候选索引并重算金额（离线重建，不强制联网）；索引恢复时校验键能由保留
  的原始名称重新推导，不一致即视为其它规则写入并重建。前端费用视图快照版本
  随之递增（9），旧规则算出的金额不被恢复。
- **两阶段候选选择（缓存读取定价解析，2026-10-06）**：候选按请求条件
  计价后先分**完整**（实际产生 token 的分项都有可解析价格）与**不完整**
  两组；在完整候选中取费用最高者（`reason = highest_complete_cost`），
  没有完整候选才回退部分候选中已知费用最高者（`highest_partial_cost`）
  ——缺价分项不得按 0 与完整候选比较。完整候选胜出但存在被排除的不
  完整候选时，breakdown 附带 `excluded_candidate_warning`（结果不是
  所有渠道的严格上界）与三个诊断计数；部分候选回退时 unknown token
  照常进入 `unknown_tokens`。
- **分段计价（Task 1/2/3/4）**：规范区间 `[min_tokens, max_tokens)`
  左闭右开，basis 为 `prompt_tokens = input + cache_write + cache_read`
  （output 不参与档位选择）。models.dev `tiers`（`type=context`）语义
  为 size = S 时短档覆盖 prompt <= S、高档从 S+1 开始，快照存转换后的
  规范分段；`context_over_200k` 仅在无等价 tiers 时生效。OpenRouter
  `overrides` 的 `min_prompt_tokens` 按**包含**下界命中（快照保留原
  语义）；两者同名数字不共用未转换的边界。外置 TOML 支持
  `[[model.segment]]`（`[min, max)`，末档省略 max_tokens 即无上限）与
  可选 `basis`/`application`（当前仅支持 `prompt_tokens`/
  `whole_request`，其他值显式拒绝）；非法条目整条忽略并给出诊断，不
  静默回退。
- **峰谷时间规则（Task 4A）**：外置 `[[model.schedule]]` + `period`
  （时区、`HH:MM`–`HH:MM` 左闭右开窗口、可选星期限制、价格覆盖）。命中
  档的价格层序为 分段显式值 > 时间规则值 > 基础价；同一候选多条规则
  同时命中时各自计价取最高（不从不同规则拼价）。时间档按**事件时间戳**
  与规则时区换算，不读当前墙上时钟。OpenRouter 带 `utc_start`/`utc_end`
  的时间条件 override 暂未接入时间引擎，同步时跳过并记 warning。
- **未命中时间规则的适用性（修复后复核 F02）**：请求时刻没有任何
  `period` 命中的时间规则，只有存在**明确声明**时才保持适用——规则级
  `prices` 任一分项为显式数值（含 0）或 `same_as_input`，或当前 prompt
  token 命中该规则分段且命中段含显式覆盖。未命中的空规则（仅有标签/
  时区/窗口结构）整体跳过，**不得**把基础价作为该规则的"默认价"重新带
  入竞争，也不得贴该规则的时间档标签；所有规则均不适用时按默认计划
  （基础价 + 默认上下文分段）参与一次。规则命中的情况不变：缺字段仍
  逐字段继承基础价。
- **请求级 breakdown（Task 5/6）**：`EventRow.cost_breakdown` 与
  `cost_usd` 来自同一次估算（不变量 7，前端不重算）：命中候选（原始键/
  渠道/来源/匹配方式/时间档）、计价依据与依据值、命中分段标签、四类
  分项的 token/单价/小计/是否计价、总价与未计价 token。未计价分项
  （缺价）不按 0 计入；`complete = false` 表示部分计价。
- **索引/快照版本（Task 9）**：价格索引 **v7**（末段匹配键 + 计划结构 +
  三态单价 + 恢复入口统一校验）。v6 及更早索引一律**拒绝读取**、按来源
  原子重建——v4/v5 可能携带被错误置 Unknown 的缓存价（R01），v6 可能
  携带未校验的非法扁平价（F04/F05）；models.dev 快照 v3 / OpenRouter
  快照 v2 写入分段，旧版本快照按"仅基础价"离线读取，不伪造分段。
- **非法单价与金额溢出（修复后复核 F04/F05）**：合法单价 = 有限且非负，
  所有入口共用同一校验——外置 TOML（含时间规则本体/时段/规则分段）、
  OpenRouter 同步（基础四价与每个 override；任一显式数值非法 → **整条
  模型拒绝**并给出含模型与分项的告警，不得丢弃脏规则后按基础价完整
  计费）、索引恢复（plan 与旧扁平字段先归一成完整计划再校验，任一条目
  非法 → 整份索引按来源重建；显式 0 合法保留）。估算阶段先除后乘避免
  有限单价的中间溢出；token × 单价仍超出 f64 表示范围时该分项**不计
  金额**、token 计入未计价并带 `overflow` 结构化原因（明细显示"金额超
  出可表示范围"），不得夹成 0/最大值或伪装 `complete=true`。
- **单价三态（缓存读取定价解析，2026-10-06）**：每类单价区分
  `Unknown`（未知：缺价 ≠ 免费，token 进 unknown）、`Fixed(v)`（明确
  数值，显式 0 = 免费）与 `SameAsInput`（显式声明沿用输入价）。仅
  `cache_read` 允许声明 `same_as_input`，其他分项遇到该值在加载阶段
  整条拒绝。解析顺序：先解析最终输入价（分段 > 时间档 > 基础价），再
  让 `SameAsInput` 引用**同层**解析出的输入价——分段档引用分段输入价、
  峰谷档引用该档输入价；输入价本身未知时保持未知。models.dev /
  OpenRouter 的缺失 `cache_read` 一律保持 Unknown，**不**全局推断为
  输入价。
- **外置 `[[model_policy]]`（缓存读取定价解析）**：为价格快照缺
  `cache_read` 的候选显式声明"缓存读按输入价"：

  ```toml
  [[model_policy]]
  prefix = "gpt-5.4"        # 末段模型匹配
  channel = "zenmux"        # 可选；省略 = 匹配所有同末段候选
  cache_read = "same_as_input"
  ```

  只改写候选缺失的 cache_read（已有明确数字/显式 0 不覆盖），不生成
  新候选；没有候选命中时给出 warning，不静默制造价格。

- 事件时间戳一律**存 UTC**（`jiff::Timestamp`），缓存与导出均为 UTC。
- 展示/聚合按解析链解析时区：显式指定 > 本机时区 > 默认 Asia/Shanghai。
- 「近 N 天」与 from/to 闭区间按**解析时区的自然日**解释（非滚动 24h 窗口）。

## 5. 外部来源导入（cc-switch，H05，2026-10-10）

导入只由用户在设置页手动触发一次（不自动、不重试、不后台同步），来源库一律
**只读**打开；导入结果进入统一历史库，与原生采集求并集。

- **输入归一化**（与 CCS 的 `fresh_input_sql` 同口径，已按其 `main` 分支源码
  与本机库核实）：`input_token_semantics` `0` = legacy（`input_tokens` 含缓存读）、
  `1` = total-inclusive（含缓存读与写）、`2` = fresh（已是非缓存输入）。
  **cache-inclusive 应用**（`codex` / `gemini` / `grokbuild`）按语义扣减；
  Claude 自身的 `input_tokens` 不含缓存，任何语义都不扣。扣减前提不成立
  （如 `cache > input` 的畸形行）时保留原值，绝不产出负数。
- **有效用量过滤**：会话日志来源的行（`data_source` ∈ `session_log` /
  `codex_session` / `gemini_session` / `opencode_session`）若在同一应用下存在
  指纹相同（输入/输出/缓存读相同、缓存写按三分支兼容）、模型相同、时间窗
  ±10 分钟的成功 proxy 行，则视为同一次请求的副本，不重复导入（等价于 CCS 的
  `effective_usage_log_filter`）。跳过这一步会把这批行当成独立请求重复计费。
- **请求身份**：Claude 会话导入的 `request_id` 形如 `session:<message.id>`，
  与 `session_id` 合起来正是本工具的 `claude-message = <session_id>|<message.id>`
  —— 两侧因此绑定到同一条历史事件（不重复计费）。Codex 的 `token_count` 不带
  请求标识，导入侧**不猜测**身份，只按来源记录键去重。
- **时间与精度**：`created_at` 是 Unix 秒，作为秒级事件时间保存，不伪造纳秒。
- **项目归属**：请求明细没有 cwd/project 列，项目保持未知，不按模型、日期或
  同步文件路径猜分配；后续原生采集可以补齐同一请求的项目与时间精度。
- **日汇总**：CCS 会把 30 天前的明细归并成日粒度并删除明细，因此两张表都要
  导入。日汇总保存在 `ccs_daily_usage`，**不伪造成请求事件**、不与明细相加；
  归一化后其输入口径标记为 fresh(2)。同键快照内容相同则跳过；内容不同且来源
  没有可验证修订时**计冲突**并在预览列出，默认保留已存值，只有用户在本轮预览
  中明确选择"以来源为准"才替换。
- **净新增**：同一请求重复导入只做必要更新，完全相同的记录跳过且不递增
  查询 generation；净新增用量按本批次的来源证据求和，不把两个来源相加。

## 6. 存储：统一历史库与解析指纹

- **事实源（H04，2026-10-10）**：归一化用量持久保存在 `~/.tokenscope/history.db`
  （WAL + 外键 + 持久同步）。事件来源键 = `native|app|规范化路径|行序|内容指纹`：
  内容不变则重复采集幂等跳过；同一行内容变化（文件被替换、新请求占用同一行）
  产生**新**事件而不覆盖旧事实；流式终值更新由原生身份别名命中同一事件完成。
- **来源删除不删用量（不变量 3）**：来源文件被删除、来源被停用、改采集目录、
  重扫日志或重置指纹，都只停止/重置新采集，已保存的用量仍可经应用筛选查看。
- **解析指纹**：由历史库 `source_files` 承接——键 = `(app, 根集合, 规范化路径)`，
  指纹 = `(size, mtime_ms)`，另带解析上下文修订（如 Claude 项目映射）。
  三者一致且文件类型未变 → 本轮不重解析；换根、换 agent 或上下文修订变化
  都会重新解析（结果与强制重扫一致）。
- **重扫日志**（界面原「重建缓存」）：重置采集指纹并重新解析当前文件，
  **不**清用量；历史删除不是缓存操作，本期不提供自动保留期或自动清理。
- **损坏语义**：历史库损坏、版本高于本程序或迁移失败 → 明确报错并保留文件，
  不删表重建、不静默用"现存日志的临时扫描"顶替完整历史（与旧缓存"故障即
  降级为全量扫描"的语义不同——历史库是事实源，不是纯优化）。
- **遗留迁移（H03）**：旧 `cache.db` 在任何版本重建/purge 之前被**只读**打开
  一次，逐条只迁合法字段（不合法行计数跳过），整批成功后才写一次性标记；
  失败可原样重试，源文件已被清理也不影响已缓存用量。
- **计数字段**：来源采集统计里的 `duplicates_dropped` 是**本轮解析**的产物
  （指纹命中轮次没有解析，自然为 0）；请求数 / 四桶 / 费用 / 分组在三路径
  （首次、指纹命中、重扫）必须逐字段一致。
- 测试密闭性：所有测试注入临时数据目录（`cache_dir` 同时作为历史库隔离根），
  禁止触碰真实 `~/.tokenscope`。

## 6.5 审阅修订（2026-10-10，H01–H08 复审）

复审发现的缺陷与最终口径（每项都有定向回归测试，见 `tests/review_regressions.rs`）：

- **IPC 字段命名**：`ImportPreview` / `ImportReport` / `CcsSchema` / `RollupCoverage` 一律**蛇形**命名，
  与 `SummaryReport` / `EventRow` 同一套约定。早期误加的 camelCase 改名会让前端读到 `undefined`
  （预览计数渲染报错、`plan_id` 拿不到、仪表盘时区提示整段消失）；字段名由
  `ipc_payload_field_names_are_snake_case` 锁定，前端 `types.ts` 逐字段对应。
- **流式读取不得自锁**：历史库行索引改为 keyset 分批读取（游标 `(ts_seconds, ts_nanos, id)`），
  **回调在锁外执行**。早期实现持锁遍历、回调里再取同一把非重入锁：5000 条明细 + 存在日汇总时查询挂死。
- **跨来源身份只认可证实证据**：
  - Claude 的 `(session_id, message.id)` 是跨来源身份；**会话行因"与 proxy 行重复"被剔除时，
    它携带的原生别名必须转移给被保留的 proxy 行**——否则原生采集会为同一请求再建一条事件（重复计费）。
  - Codex 的 `token_count` 没有请求标识：与本地已有请求"同应用 + 同模型等价身份 + 同四桶 + 时间接近"时
    只作**重叠候选（线索）**处理——预览列为未解决，**默认拒绝提交**；用户显式确认后才按新增导入，
    并在批次审计里标出条数。时间与用量相同不足以认定是同一次请求。
  - 同源去重另用**保守重播身份**（`(session_id, 原始模型, 四桶)`，与 §3.2 的 Codex 重播规则同源）：
    文件归档移动、出现副本、遗留缓存迁移后重扫都命中同一事件——持久化身份**不含文件路径**。
- **终值观察时间**：原生写入的 `observed_at` = **事件时间**（不再用采集时刻）。重新解析一份较旧的副本
  不会把已保存的较新终值回退；同一请求的流式更新仍按"事件时间更晚者胜出"。
- **日汇总主键完整**：`request_model` 参与 CCS 日汇总的主键读取与入库键——仅该列不同的合法汇总不再折叠。
- **时间范围同样作用于日汇总**：按日期/天数筛选时，只有日粒度的历史也受该范围约束（限定范围时，
  日期无法解析的行一律排除）；`rollups = detail_only` 时完全只用请求明细（§5.2 的恢复路径之一）。
- **明细分页不绕过预算**：分页按批读取事件（每批至多 256 条，内存与批大小成正比），
  `limit=1` 的请求不再物化整份历史；会话保留量与实际保留对象一致。
- **单条坏记录不回滚整批**：适配器把空模型等坏行计 `bad_lines` 跳过；采集侧写入前再按条预检，
  坏记录只计诊断，其余用量照常入账，已有历史仍可查询/展示。
- **遗留迁移整批原子**：全部事件与"已迁移"标记在**同一个写事务**提交，失败保持事务前状态（可原样重试）。
- **净新增 token**：只统计**本批新增**事件的四桶之和；只给已有请求补来源证据时为 0。
- **子代理上下文**：sidechain 行有**自己的**项目根与初始目录——独立子代理日志的可信 cwd 不再被丢弃，
  但它的 cwd 不推进主链项目根（§3.4 的隔离要求不变）。
- **采集统一单飞**：启动采集、手动刷新、重扫与定时采集共用一个串行闸门；不同参数的调用**排队**而非并行
  （同参调用仍复用同一航班，零重复解析）。
- **来源库一致读事务**：CCS 的结构探测、请求明细与日汇总在同一个只读事务内读取。
- **提交在事务内校验 generation**：预览之后、提交之前的任何采集/导入都会让整批拒绝并要求重新预览。
- **升级前备份**：历史库结构升级前用 `VACUUM INTO` 生成可恢复副本（`history.db.backup-v{N}`，
  已存在不覆盖；备份失败即中止本次升级）。

### 6.5.1 复审第二轮修订（2026-10-11，隔离探针发现的遗漏）

- **旧历史库补齐 Codex 重播身份（schema v3 数据迁移）**：v2 时代的原生事件没有 `codex-usage`
  别名，而已采集文件的指纹命中让重解析不再发生——文件移动到归档目录后找不到旧事件、重复计量。
  升级时从库内字段重建该别名（同身份对应多个事件时无法唯一改绑，保持缺失）。
- **旧观察时间迁移为事件时间（schema v3 数据迁移）**：v2 及更早版本把采集时刻存进 `observed_at`，
  升级后按事件时间判定终值——旧记录总被判过期。迁移把全部 `observed_at` 改写为事件时间，
  此后真实终值照常按更新处理。
- **并集与导入顺序无关**：CCS 对带 `session_id` 的 Codex 行登记与原生采集**同构**的保守重播身份
  （`codex-usage = session|模型|四桶`），"先导入后采集"与"先采集后导入"命中同一事件、得到相同并集；
  这是沿用 §3.2 的保守规则（同模型同用量的独立请求可能被合并），不是宣称强跨来源身份。
  缺 `session_id` 的行仍按身份不足处理（重叠候选，默认拒绝提交）。
- **优先级先于观察时间**：原生日志比 CCS 导入更可信——同一条请求的原生记录无论事件时间是否早于
  已存 CCS 值都胜出（CCS 的 `created_at` 稍晚几秒时，后采集的原生终值不再被误判为过期）；
  观察时间只在**同优先级**内区分新旧。CCS 后到仍按冲突保留原生值。
- **日汇总身份不含 `source_tz`（schema v3 重建表）**：来源统计时区是导入时记录的假设，不是数据身份。
  同一 CCS 库改选时区再次导入修订该假设，不产生第二份快照、不重复累计请求；
  v2 时代仅时区不同的重复行折叠为最早一条（与 KeepExisting 策略一致）。
- **行索引预算计入 `record_id` 堆内存**：查询快照的轻量行索引按元素定长计账，`record_id` 是堆
  `String`——长记录标识成批绕过会话预算。现在逐行计入字符串本体。
- **「只看请求明细」随视图快照保存/恢复（快照 v11）**：该模式是用户显式选择，重新进入页面必须恢复，
  不再静默回退成 auto 重新带入日粒度历史；v10 及更早快照整体忽略（旧版不含该字段）。
